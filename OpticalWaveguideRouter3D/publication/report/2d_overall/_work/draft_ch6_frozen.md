# 第 6 章 冻结公平对照与保护性优化

本章回答三个问题：逐路半径与端点冻结后，只加几何约束（间距、小角度交叉惩罚）能把风险降到什么程度、代价是什么；压力情景放大后结论是否仍成立；能否在不伤害关键路线的前提下局部改进。数据均来自已有二维（opt2d）产物，不重新运行优化。

## 6.1 为什么必须先冻结逐路半径与固定保护集合

**不冻结会污染三类比较。** 一是配置之间的横向比较：Step 13 允许规划器自适应选半径，数字里混着“约束效果”与“半径选择效果”。同为 256 通道，自适应半径下 spacing / small / both 的 <20° 交叉为 626 / 434 / 369，平均损耗 2.9734 / 2.9930 / 2.9902 dB [OpticalWaveguideRouter3D/outputs/opt2d_step13_constrained/256/constrained_comparison.csv]；冻结半径后同样的比较变成 622 / 315 / 371 与 2.9724 / 2.9986 / 2.9887 dB [OpticalWaveguideRouter3D/outputs/opt2d_step14/256/comparison.csv]，small 的 <20° 交叉由 434 降到 315，平均代价却由 +0.0227 升到 +0.0283 dB。二是逐路归因：半径一变，弯曲损耗与几何同时变，保护路线的增减无法再归因于约束；256 与 512 的半径分布本就不同。

**做法与冻结证据。** 先跑一次补修后的 F56 取得逐路半径表，所有配置（base、spacing、small、touch、both 与优化）都通过 PlanConfig.radius_overrides 传入该表；端口身份、端点槽位与 150 × 150 mm 板尺寸沿用 Step 13 冻结设置 [OpticalWaveguideRouter3D/docs/reports/step_14_opt2d_frozen_robust_optimization.md]。冻结是否生效由逐路核对表证明：256 的 256 行中 f56_radius_mm 与 frozen_radius_mm **全部相同（256/256，错位 0）**，全为 R6 = 6.0 mm；512 为 **512/512 相同**（6.0 mm 的 510 条、5.0 mm 的 2 条） [OpticalWaveguideRouter3D/outputs/opt2d_step14/256/radius_freeze_check.csv；…/512/radius_freeze_check.csv]。

**冻结没有改变基准。** 256 的 base 与 references.csv 的 F56 行逐项相同：平均 2.9702981166542815 dB、P95 4.654524100438386 dB、最大 5.078297843737668 dB、<20° 657、最差路线 #34；512 同样逐项相同：平均 3.2946845970804954 dB、最大 5.499482735795704 dB、<20° 2939 [OpticalWaveguideRouter3D/outputs/opt2d_step14/256/comparison.csv、…/256/references.csv；512 同路径]。256 的 base 还与 Step 13 补修后的 base 完全一致（平均 2.9702981166542815 dB、<20° 657、间距违规 415）[OpticalWaveguideRouter3D/outputs/opt2d_step13_constrained/256/constrained_comparison.csv]。

**保护集合一次性确定、所有方案共用**：256 与 512 各 11 条 route_id。256 为 base 最差 #34、D56 最差 #44 与被穿越最多的 10 条 U 型；512 为 #34、#287（512 的 D56 最差）与被穿越最多的 10 条 U 型（#34 与 U 型重复，去重后 11 条）[OpticalWaveguideRouter3D/outputs/opt2d_step14/256/protection_set.json；…/512/protection_set.json]。规则为“base 最差 + D56 最差 + 按 crossing_count 降序取前 10 条 U 型”[OpticalWaveguideRouter3D/src/opt2d/step14.py:121-138]。比较必须看逐路结果（均值会掩盖个别路线的明显变差，见 6.3）。

## 6.4 压力情景 ×1 / ×2 / ×5 / ×10

## 6.5 验收结果：256 在严格口径下零接受、512 在 ×10 下未改善

## 6.6 结论边界：已支持、未验证与负结果

**已支持。**（1）冻结下 256 与 512 的 base 都等于补修 F56（逐项相同），冻结未改变基准。（2）256 上间距或小角度约束能显著降低相应风险（<20° 交叉 657→315、间距违规 415→275），平均代价 +0.002~+0.028 dB，但每种配置都会让 1~3 条保护路线标称上浮 0.0017~0.0092 dB。（3）512 上只有保护性局部优化同时满足全部验收条件（6 条接受：风险 −0.092 dB、平均 −0.001 dB、保护对象零越界）；spacing 与 both 伤害关键链路 0.27~0.39 dB，实质不可接受。（4）touch 在两规模都无作用（物理接触数为 0）。

**未验证或不应宣称。**（1）×1 / ×2 / ×5 / ×10 是人为压力情景，不是实测误差范围；全部损耗都是现有损耗模型的计算值。（2）“×10 情景由极小角交叉支配”缺少产物支撑（见 6.4）。（3）平均与 P95 都是一次布局内逐路线统计，非重复实验统计；P95 采用 ⌈0.95N⌉ 步进口径，引用时须注明。（4）运行时间每项只有一次记录（touch 与 base 几何逐项相同而用时 27.8 s 与 55.7 s），不能据此宣称效率优势；512 opt_base 的 comparison.csv 中 runtime_s = 0.0 是占位值，762.24 s 取自 optimize_record.json 的搜索计时，不可与其它行的布局评价时间并列。（5）报告 §3.2“求交边界容差修复后既有评价逐项完全一致”无法由产物核实：outputs 下只有一份 legacy_scheme_scan.csv 快照，其 256 的 F56 行（平均 2.9688948893085385、段级接触 228、重合 1、legally_valid=False）与本章 base（2.9702981166542815、226、0）不是同一状态。（6）报告 §6.1 称目标路线 22 条（256）/ 26 条（512），但落盘的 attempts 只覆盖 17 条（256，68 次尝试）与 22 条（512，74 次尝试）；按实现，候选为空的路线不写入记录，差额可由代码路径解释，但 22 / 26 本身无产物可印证。

**必须如实保留的负结果。**（1）256 在任务规定的严格口径下 **0 接受**，保持 base 不变。（2）512 的 opt_base 在 **×10 情景下未改善**（+0.0663 dB）。（3）512 的 spacing 把 <20° 交叉从 2939 抬到 3263、<5° 从 53 抬到 106；both 的 ×5 情景最大比 base 高 0.4682 dB。（4）零余量逐路验收下，256 与 512 的全部约束配置（spacing / small / both）都被拒绝。

**核查更正。** 本章数值以原始 CSV 为准：报告 §5 的 256 表中 #177 的 spacing 变化应为 −0.0043 dB（报告写作 −0.0044）；报告 §5 的 512 表中 #154 的 spacing 变化应为 −0.0104 dB（报告写作 −0.0105），#34 的 small 变化应为 −0.0253 dB（报告 §5 写作 −0.0254，与其 §7.2 自相矛盾）；报告 §7.3 中 both 的 ×10 变化应为 +0.1429 dB（报告写作 +0.1428）。半径单位以产物为准为 mm（radius_freeze_check.csv 列名 f56_radius_mm，取值 5.0 / 6.0），内部约定文件“R5/R6 单位 μm”与产物冲突。
