# Step 14：冻结对照下的二维稳健优化

本轮在 Step 13 补修后的 F56 之上做三件事：**冻结公平对照**（同一批半径、同一批保护
对象）、**以风险为目标的约束优化**（压力情景 = <20° 交叉损耗 ×5）、以及**统计口径统一**
（物理接触 vs 解析段接触）与**求交边界补测**。全部在二维范围（`src/opt2d/`），
旧产物一律保留，新产物在 `outputs/opt2d_step14/`。

## 0. 摘要

| 问题 | 结论 |
| --- | --- |
| 冻结半径后 base 还是 F56 吗？ | 是。256 逐路半径 256/256 与 F56 一致，平均/最大/交叉数逐项相同 |
| base 与 D56/F56 的公平对照 | 全部配置传入 `radius_overrides`；256 全 R6、512 见 §4；保护对象两规模各自固定为同一批 route_id |
| 约束配置能降风险吗？ | 能。压力情景（×5）最大损耗：spacing −0.043、small −0.055、both −0.052（256）；×10 情景下 small 把最大损耗从 5.9941 降到 5.2192 |
| 代价是什么？ | 标称平均 +0.002~+0.028 dB；**3 条（small）/1 条（spacing、both）保护路线的标称损耗轻微上浮（最大 +0.0092 dB）** |

## 1. 冻结公平对照

### 1.1 冻结内容

* **连接身份与端点**：沿用 Step 13 的冻结端口（`frozen_ports_frame`），
  端口槽位交换保持关闭；
* **半径**：先跑一次补修后的 F56 取得**逐路半径表**，随后所有配置
  （`base / spacing / small / touch / both` 与优化）都通过
  `PlanConfig.radius_overrides` 实际传入该表；
* **板尺寸**：150 × 150 mm 不变。

逐路核对（`radius_freeze_check.csv`）：256 通道 256/256 条路线的冻结半径与原
F56 完全一致；`base` 方案的平均（2.970298）、最大（5.078298）、交叉数（657 个
<20°）与 Step 13 补修后的 F56 **逐项相同**，说明冻结没有改变 base。

### 1.2 固定保护集合（一次性确定，所有方案同一批）

| 角色 | 256 | 512 |
| --- | --- | --- |
| base 最差路线 | #34 | 见 `protection_set.json` |
| D56 最差路线 | #44 | 见 `protection_set.json` |
| base 中被穿越最多的 10 条 U 型 | #34, #9, #186, #185, #177, #43, #35, #52, #10, #11 | 见 `protection_set.json` |
| 去重后共 | 11 条 | 见 `protection_set.json` |

每个方案的产物都带 `protection_routes.csv`：**逐条**列出保护路线的总损耗、
相对 base 的变化、交叉数与 <20° 交叉数 —— 比较不看集合均值（见 §5）。

### 1.3 与 Step 13 受约束实验的区别（纯约束效果 vs 半径变化）

Step 13 补修的受约束实验（`outputs/opt2d_step13_constrained/`）里，半径是**自适应**
选出来的（F5/F56 的候选网格含 R5/R6）；本轮的 `base/spacing/small/both` 全部**冻结
半径**。两次实验在 256 的对照：

| 配置 | Step 13（自适应半径）<20° / 平均 | Step 14（冻结半径）<20° / 平均 |
| --- | --- | --- |
| base | 657 / 2.9703 | 657 / 2.9703（与 F56 相同） |
| spacing | 626 / 2.9734 | 622 / 2.9724 |
| small | 434 / 2.9930 | 315 / 2.9986 |
| both | 369 / 2.9902 | 371 / 2.9887 |

结论：**Step 13 的数字里混着半径选择的影响**；冻结半径后 small 的小角交叉降得
更多（315 vs 434），平均代价略升（+0.0283 vs +0.0227）。本报告之后所有比较都以
冻结半径为准。

## 2. 实现：受约束优化与验收

### 2.1 局部重布与验收（`src/opt2d/step14.py`）

* 从完整、合法的 base 出发，按"保护集合 ∪ 压力情景损耗最高的 16 条"逐条尝试；
* 每次尝试：移除该路线 → 枚举其候选（U 型轨道候选 + 自由弯角角度候选，
  每路最多 4 个） → **完整评价整个布局**（不是增量近似） → 验收；
* 验收规则（:class:`AcceptanceRule`，已接入实际执行路径）：

  | 规则 | 阈值 |
  | --- | --- |
  | 完整连接 | 必须 |
  | 重合 / 单路几何违规 | 0 |
  | 标称平均损耗 | ≤ base + **0.05 dB** |
  | 标称全局最大损耗 | ≤ base |
  | 固定保护对象**逐路**标称损耗 | ≤ 各自 base |
  | 端点 / 半径 | 零变化 |

* 主目标：**压力情景（<20° 交叉损耗 ×5）的全局最大损耗严格下降**。
  压力情景是实验情景，用于把"小角度交叉表不可信"这一风险变成可优化的目标，
  **不声称代表真实误差范围**；
* 不满足即**完整回滚**（`Planner.restore` 到快照）并逐次核对 `state_fingerprint`；
* 记录候选数、接受数、拒绝原因、运行时间（`optimize_attempts_*.csv`、
  `optimize_record.json`）。

### 2.2 小角交叉与间距：分开配置

| 配置 | `small_angle_penalty_db`（<20° 每事件） | `spacing_penalty_db`（每路线对） | `touch_penalty_db`（每物理事件） |
| --- | --- | --- | --- |
| base | 0 | 0 | 0 |
| spacing | 0 | 0.05 | 0 |
| small | 0.05 | 0 | 0 |
| touch | 0 | 0 | 0.05 |
| both | 0.05 | 0.05 | 0 |

接触惩罚已与间距惩罚**分开配置**（`PlanConfig.touch_penalty_db`），但本轮
`touch` 配置与 base **完全相同** —— 因为物理接触数为 0（见 §3），没有作用对象。

## 3. 统计统一与求交边界补测

### 3.1 raw 段级接触 vs 物理接触

新增两套口径（`summary`）：

* `raw_segment_touch_count`：`spacing_report` 的**解析段级**接触（含重复计数）；
* `physical_route_touch_count`：`pair_events` 按位置聚类、**按整条路线合并**后的
  物理接触；同时新增 `raw_segment_cross_count` 与 `unique_crossing_events` 对照。

实测（Step 13 补修后的方案）：

| 方案 | raw 段级接触 | 物理接触 | raw 段级交叉 | 唯一物理交叉 |
| --- | --- | --- | --- | --- |
| 256 D0 | 400 | **0** | 9676 | 9474 |
| 256 D56 | 452 | **0** | 9790 | 9564 |
| 512 A / R5U / D0 / D56 | 0 | 0 | — | — |
| 512 F5 | 5 | **0** | — | — |

即：Step 13 报告里 D0/D56 的"400/452 个接触"全部是**解析段端点处的真实交叉
被段级判定误报为接触**；按整条路线合并后物理接触为 **0**。这两套数都保留，
报告一律注明口径。

### 3.2 求交边界：两类容差分开

`src/opt2d/intersections.py` 原先把"求解残差"与"有限段边界"用同一个容差
（`max(tol, scale·1e-7)` ≈ 150 mm 尺度下 1.5e-5 mm）。现在分开：

* **求解残差容差** `residual_tol = max(tol, scale·1e-7)`：数值可解性，
  两个参数解点之间的允许差；
* **有限段边界容差** `edge_tol = max(tol, scale·1e-9, 4·eps·scale/|sin|)`：
  几何语义（超出端点多少算"段外"），并与参数解不确定度取大，避免近乎平行时
  边界判断随舍入抖动。

补测用例（`tests/test_opt2d_step13_fixes.py` 扩展）：

| 情形 | 结果 |
| --- | --- |
| 极小夹角（1e-7 rad）的真实相交，交点在段内 | 判 `cross`，交点位置正确 |
| 交点在端点外 1e-9 mm（< edge_tol） | 视为在段上（有事件） |
| 交点在端点外 1e-7 ~ 1e-3 mm（> edge_tol） | **无事件**（旧实现在 1e-6 量级会误报） |
| 极小夹角 + 交点明显在段外（1e-4 mm） | 无事件 |

**对既有结果的影响**：用修复后的实现重新扫描 256/512 的全部已存方案
（`legacy_scheme_scan.csv` 前后对比），评价结果**逐项完全一致** ——
因此本轮不需要重新评价任何已存方案。

`spacing` +0.3885（#311）—— 后三者**在任何合理余量下都不通过**。

对比得到两条规模结论：

* 256 上"约束配置"是温和的（越界 ≤ +0.0092），只是被零余量规则挡住；
* 512 上 `spacing`/`both` 会**大幅伤害**保护路线（#311 +0.34~+0.39、#287 +0.27~+0.34），
  属于真正不可接受的方案；`small` 也越界 +0.024。**512 上只有保护性局部优化
  （opt_base）同时满足全部约束。**

且含最差的两条）。这是**搜索空间大小**的差异，不是规则宽严的差异。

### 6.2 诊断口径：候选排序强度与保护余量

**256 通道**：把保护余量放到 +0.01 dB（**明确是诊断，不是任务口径**）后，同一搜索

| ×5 情景最大 | 5.1803 | **5.1742（−0.0061）** |
| <20° 交叉 | 657 | 632 |
| 回滚指纹错位 | — | 0 |

余量 +0.05 得到与 +0.01 相同的结果，说明限制因素不是余量大小，而是"情景最大必须
严格下降 + 平均预算"这两个条件本身。把候选排序强度再调到 2.0 也不改变结论。

**512 通道**：同一诊断（420 s 预算）在**严格口径下就已接受 5 条**（`probe_summary.csv`）：

### 6.3 如何解读

* **512**：验收规则可以被满足 —— 优化找到 6 条"只改善自己、不碰保护对象"的候选，
  同时把 ×5 情景最大压低 0.092 dB、标称平均还改善了 0.001 dB。这说明
  "降风险 + 护最差链路"在本邻域内**是可能的**，但需要搜索空间足够大；
* **256**：同一套规则下 0 接受。候选要么减不了情景最大（62/68），要么抬高了标称
  最大（32/68），要么让某条保护路线 +0.001~+0.009 dB。任务允许的"平均 +0.05 dB"
  预算很宽（实际用掉 ≤ 0.028），**逐路保护的无余量硬约束**才是决定性的；
* 因此如实报告：**256 严格口径保留 base（未找到满足约束的改进）**；512 采用
  `opt_base`（6 条接受的累积结果）。两者都给出了余量诊断，量化"放松 epsilon
  能换多少风险下降"。

## 7. 结论（分开陈述收益与代价）

### 7.1 平均收益

冻结半径后，相对 base 的平均损耗变化：

| 规模 | spacing | small | both | opt_base |
| --- | --- | --- | --- | --- |
| 256 | +0.0021 | +0.0283 | +0.0184 | 0（未接受任何改进） |
| 512 | +0.0677 | +0.0545 | +0.1081 | **−0.0011** |

256 的三个约束配置都落在 +0.05 dB 预算内；512 的 `spacing` 与 `both` **超出预算**
（+0.068 / +0.108），`small` 也到 +0.0545。唯一在 512 上平均不升反降的是
保护性优化（opt_base）。

### 7.2 最差链路收益（标称口径）

标称全局最大损耗相对 base 的变化：

| 规模 | base | spacing | small | both | opt_base |
| --- | --- | --- | --- | --- | --- |
| 256 | 5.0783 | −0.0160 | −0.0274 | −0.0243 | 0 |
| 512 | 5.4995 | **+0.0414** | −0.0253 | −0.0118 | **−0.0341** |

256 的三个配置都改善全局最差链路；512 上只有 `small` 与 `opt_base` 改善，
`spacing` 反而让最差链路更差。**但全局最差链路不等于保护对象**：256 的三个配置
仍分别让 1~3 条保护路线标称上浮（§5），这份"逐路的账"才是本轮的主要代价。

### 7.3 风险改善及其代价

（风险 = <20° 交叉损耗 ×5 的压力情景；全部为固定几何复算。）

**256**

| 口径 | base | spacing | small | both |
| --- | --- | --- | --- | --- |
| 标称平均 | 2.9703 | +0.0021 | +0.0283 | +0.0184 |
| 标称最大 | 5.0783 | −0.0160 | −0.0274 | −0.0243 |
| ×5 情景最大 | 5.1803 | −0.0432 | −0.0546 | −0.0515 |
| ×10 情景最大 | 5.9941 | −0.2516 | **−0.7749** | −0.6970 |
| <20° 交叉数 | 657 | 622 | **315** | 371 |

| <5° 交叉数 | 22 | 10 | 11 | **6** |
| 间距违规 | 415 | **293** | 377 | 275 |
| 保护路线最大越界 | 0 | +0.0072 | +0.0092 | **+0.0021** |

**512**

结论：

1. **小角交叉三档全部下降**（没有出现"总数降、极小角升"）只发生在 `small`
   （两规模）与 `both`（256）；512 的 `spacing` 连 <20° 总数都涨了（2939→3263）；
2. **风险改善随情景强度放大**：×1 口径下差异 ≤0.03 dB，×10 口径下 `small` 的
   最大损耗比 base 低 0.775 dB（256）/ 0.950 dB（512）；
3. **代价集中在"逐路保护"**：256 是 0.002~0.009 dB 的轻微上浮，512 的
   `spacing`/`both` 则是 0.27~0.39 dB 的实质伤害（#311、#287）；
4. **唯一两规模都通过全部约束的是保护性局部优化**：256 保持 base（0 接受），
   512 接受 6 条（风险 −0.092、平均 −0.001、保护对象全部不劣化）；
5. `touch` 配置在两规模都无作用（物理接触数为 0）—— 这条是统计口径统一后的
   直接结论：旧报告的"接触"数字不构成优化目标。
