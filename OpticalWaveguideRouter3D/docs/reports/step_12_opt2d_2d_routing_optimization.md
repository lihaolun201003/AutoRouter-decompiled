# Step 12：二维布线优化实验（opt2d）

本报告记录在**相同端点、板尺寸、线宽、间距与损耗模型**下，对原版 AutoRouter
二维布线（256 / 512 通道）做优化探索的完整结果：统一评价器、基线对照（A/B）、
候选轨道优化（C）、局部自适应半径（D）、消融、失败案例与限制分析。所有数字由
`outputs/opt2d/` 下的逐路 CSV 与汇总 JSON 直接生成，可用
`scripts/opt2d_run_all.py` 重跑。

## 0. 摘要

| 问题 | 结论 |
| --- | --- |
| 单纯调半径（A→B）能省多少？ | 平均 −0.9426 dB（256，−17.9%）、−0.9579 dB（512，−17.4%），几乎全部来自弯曲损耗 |
| 候选轨道优化（A→C）能省多少？ | −0.0014 dB（256）、−0.0016 dB（512），约 −0.03%，与数值噪声同量级 |
| 自适应半径（D）相对统一 R6（B）？ | 损耗持平（±0.003 dB），但把 512 的完整连接从 510/512 提到 512/512 |
| 收益天花板由什么决定？ | 固定"两弯 U 型"结构：轨道选择只影响交叉损耗，而交叉只占总损耗 2.5%（256）/ 5.8%（512） |

**本实验没有预设改善；算法层面的收益确实很小**，原因在 8.2 节逐项拆解。

## 1. 范围与复用

* 研究对象只有二维：256 与 512 通道的真实输入
  （`OpticalWaveguideRouter2D/data/fiberBoard{256,512}.xlsx`），不做三维、不改 GUI。
* `OpticalWaveguideRouter2D`（原版 AutoRouter 的精确复现）作为**基线来源**与
  **损耗模型来源**被只读复用；它的代码、数据与 `results/` 输出未被修改，
  新代码只写进本项目 `src/opt2d/`、`scripts/`、`tests/` 与 `outputs/opt2d/`。
* 本项目既有的解析几何与交叉模块被直接复用，未重复开发：
  `src.geometry`（Line/Arc 表示、长度与校验）、`src.collision`（直—直、直—弧、
  弧—弧解析求交，每对曲线返回全部交点）、`src.physical_intersections`
  （同一对路线内的位置聚类去重、真实切线夹角、cross/touch/overlap 分类）。
  新增的只有"从原版存储字段重建几何""间距检查""候选搜索"这些既有模块没有的部分。
* 运行解释器为 2D 项目的 `.venv`（3D 项目 venv 缺 `scipy`，无法导入原版
  `waveguide_calculator`）。

## 2. 统一评价器

### 2.1 原版圆弧几何的解析重建

原版 `plotter_bend` 输出的是切点 `bend_x/bend_y`、圆心 `center`、绘图角区间
`theta` 与象限方向 `dir`。本实验按**行进方向**把它们重建成
`LineSegment2D` / `ArcSegment2D` 序列：

* `dx >= 2R`：标准双 90° 圆角，两个四分之一圆弧 + 中间水平直线段；
* `0 < dx < 2R`：原版把两个**非完整**圆弧在水平中点直接相接，半角
  `theta = arccos((R - dx/2)/R)`，竖直切点距轨道 `R*sin(theta)`，无中间直线段
  （256 有 31 条、512 有 58 条属于此类）；
* `dx == 0`：单条直线。

核验方式：把重建结果与原版实际写出的 `bend_x/bend_y/center/theta/dir` 逐条比对，
256 与 512 全部一致，最大偏差 4.9e-5 mm，等于原版把切点四舍五入到四位小数的
存储界；重建出的每段弧半径与原半径的偏差 < 1.5e-14 mm。

### 2.2 交叉事件口径

* 求交覆盖**直—直、直—弧、弧—弧**三种组合，每对曲线返回**全部交点**；
* 去重只在"同一对波导、同一位置"合并重复的几何记录（坐标聚类），同一对波导在
  **不同位置**的交叉点全部保留；
* 全网唯一事件只记录一次；计算逐路损耗时，该事件**分别计入两根波导各一次**，
  禁止把逐路交叉损耗直接除以二。因此
  `per_route_crossing_events == 2 × unique_crossing_events` 恒成立
  （256: 18936 = 2×9468；512: 86786 = 2×43393）；
* 交叉角由交点处两条曲线的**真实切线**给出，包含不同半径圆弧的组合；
* 自检：在原版 256 布线上抽查全部事件的约 200 个样本，每个事件的位置都同时落在
  两条路线的解析几何上，角度都等于该点处两条真实切线的锐角。

### 2.3 两套统计

* **原版统计**：直接调用 2D 项目 `waveguide_calculator.calc_index`（含它的弦近似
  求交与角度公式），逐路给出 `length / crossing / loss`。对方案 A，本实验复算结果
  与 2D 项目已存档结果完全一致（256: 5.278787 / 6.333027；512: 5.514721 / 6.576075）。
* **解析物理统计**：本模块的逐路损耗与全部汇总指标，后续所有方案对照都用它。

| 规模 | 解析平均 | 原版平均 | 解析最大 | 原版最大 | 解析唯一事件 | 原版逐路记录 | 解析最小角 | 原版最小角 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 256 | 5.278568 | 5.278787 | 6.333325 | 6.333027 | 9468 | 18936 | 34.92° | 35.0° |
| 512 | 5.516158 | 5.514721 | 6.577295 | 6.576075 | 43393 | 86512 | 23.07° | 14.0° |

两套口径的平均损耗差在 0.0014 dB 以内（0.03%）；差异集中在**最小交叉角**
（512 为 23.07° vs 14.0°）与交叉事件数（512 解析多检出约 137 个唯一事件，
0.3%），原因见 9.2 节。

### 2.4 合法性与违规分类

* **允许的交叉**：中心线在非端点处横穿 —— 正常事件，计入交叉损耗；
* **重合（overlap）**：两条路线共用一段轨迹 —— 几何违规（本实验 A/B/C/D 全部为 0）；
* **近并行间距不足**：两段曲线不相交，但中心线最小距离小于阈值（线宽 + 标称间隔，
  256 为 0.30 mm、512 为 0.175 mm）。**该阈值是实验假设**：原版只用 `noCross`
  的端口顺序启发式，没有显式间距规则，也没有制造依据支持某个具体数值；
* **几何违规**：端点不符、切向不连续、半径不符、弯曲空间不足（构建阶段直接拒绝）、
  越界、自交。A/B/C/D 的 `geometry_issue_count` 全为 0（B 的 512 例外见 6 节）。

## 3. 基线与半径对照

| 方案 | 定义 |
| --- | --- |
| A | 原版 R5 几何（`plotter_rect` 实际输出，逐条核验与原版一致） |
| B | 统一半径 R6 **重新布线**：非法几何的轨道自动下移到最近合法轨道；这是**参数对照**，不计作算法贡献 |

把半径从 5 mm 改成 6 mm、但**只改损耗计算里的半径**是行不通的：原版轨道分配在
256 有 13 条、512 有 10 条路线会产生非法几何（切点越过端面），必须重新布线并核验。

## 4. 方案 C：候选轨道优化

在原版四遍结构内（`below → above → below2above → above2below`，保持 pass 间边界
依赖）把"取第一个可用轨道"改为**枚举全部可行候选并评分**：

* 候选枚举用原版 `noCross` 语义（逐字复刻，`candidate_limit=1` 时与原版逐条一致，
  已在 256/512 上验证 0 差异）；
* 每个候选都生成真实几何并核验（端点、切向、半径、板边界、弯曲空间）；
* 评分 = 新路线自身损耗 + 受影响**既有**路线新增交叉损耗的**两倍**贡献
  （一个交叉事件给两根波导各加一次损耗，所以对全网总损耗的增量是事件损耗的两倍）；
* 顺序策略：原版顺序 / 跨度优先 / 预计拥塞优先（见 7 节消融）；
* 有界拆线重布：只重布高损耗路线，**任何一条重布失败就整体回滚**，
  绝不以牺牲连接完整性换取损耗下降；
* 端口连接关系不变；同端口出线顺序沿用原版 `_reorder_by_port` 机制
  （`sx` 与 `lx` 两步置换，逐字复刻）。

**位置正则项**（`position_penalty`，dB/位）：纯损耗评分会把路线从原版"贴边"位置
推向中间，挤占跨区路线所需的通道，导致后续路线无可行轨道 —— 256 未布通 38 条、
512 未布通 113 条。加入"候选在扫描顺序中的位置"惩罚后完整连接恢复。该项是算法
参数（消融见 7 节），不是损耗模型改动。

## 5. 方案 D：局部自适应半径

在 C 的基础上把半径并入候选：候选 = (轨道, 半径)，首版半径取自已有实测数据的
R5 / R6。半径改变后**重新生成几何**并重算交叉事件与逐路损耗；交叉角用真实切线。
搜索按候选数量与轮数限制，保存最佳可行解与停止原因。

## 8. 收益拆解：参数收益 vs 算法收益

### 8.1 数字

| 对比 | 256 | 512 | 性质 |
| --- | --- | --- | --- |
| A→B（半径 5→6） | −0.9426 dB（−17.9%） | −0.9579 dB（−17.4%） | **参数收益** |
| A→C（候选轨道 + 重布，R5） | −0.0014 dB（−0.03%） | −0.0016 dB（−0.03%） | 算法收益 |
| A→D（自适应 R5/R6） | −0.9392 dB（−17.8%） | −0.9569 dB（−17.3%） | 参数为主 + 完整性 |

### 8.2 为什么算法收益这么小

逐项拆开平均损耗的构成（以 256 的 A 为例：总 5.2786 dB）：

* **弯曲损耗 4.5228 dB（85.7%）**：由半径与弯角决定。固定两弯 U 型下，弯角之和
  恒为 180°（两条线从同侧进出）或由 `dx` 与 `R` 唯一确定，**与轨道选择完全无关**。
  只有改半径（B/D）才能影响它。
* **直线损耗 0.6249 dB（11.8%）**：对跨区连接（below→above）总长度与轨道无关
  （`height + dx − 2R`）；对同侧连接（below→below / above→above）长度随轨道单调，
  原版"最低/最高可用轨道"已经是该方向的端点最优。C 只能通过牺牲直线长度换取交叉
  减少，实测净效果接近零。
* **交叉损耗 0.1308 dB（2.5%）**：**这是轨道选择唯一能影响的项**。即使把全部交叉
  降到 0，256 的上限也只有 −0.1308 dB（−2.5%），512 是 −0.3219 dB（−5.8%）。
  实际 C 拿到 −0.0035 dB（256）/ −0.0008 dB（512）的交叉改善，约等于上限的 1%~2%。
* 交叉难以消除的原因是结构性的：512 条/256 条跨区连接都要穿过中间通道，
  交叉是"两端点分布"决定的下界，不是路由顺序能消掉的。

**限制来源结论**：收益天花板由**固定两弯结构**（弯角固定、半径固定）与**端点分布**
共同决定；轨道空间与交叉模型都不是主要瓶颈，半径可行性只在极少数最靠边的轨道上
（512 的 2 条）才成为限制。

## 9. 失败案例与限制

### 9.1 半径可行性（B 的 512 未布通 2 条）

`#60`（track 144.650）、`#61`（track 144.825）是 `above→above` 连接，
`dx ≈ 11.2 / 10.9 mm < 2R`，因此落在"两弧在中点相接"的分支：需要的竖直空间是
`R·sin(arccos((R−dx/2)/R))`。

* R5：该值约 4.96 mm，而轨道到端面有 5.35 / 5.175 mm —— 可行；
* R6：该值升到约 5.99 mm（`dx` 接近 `2R` 时它趋近半径本身），需要轨道
  `≤ 144.01 mm`，而这两条连接可用的轨道都在 144.6 mm 以上 —— 几何构建直接拒绝
  （"start-side straight is shorter than the bend radius"）。

处理方式：

* B（统一 R6）如实报告 510/512 与 2 条未布通，不做静默修补；
* D 的自适应半径让这 2 条退回 R5，恢复 512/512 完整连接；
* 这也解释了为什么"只改损耗计算里的半径"不可行：R6 的空间需求真实存在，
  必须重新布线并核验几何。

### 9.2 交叉角的弦近似 vs 真实切线

原版 `calc_crossing` 用**折线弦**近似曲线，并对直—弧、弧—弧使用只对特定情形成立
的角度公式（弧—弧用等半径公式 `arccos(1 − d²/(2R²))`，直—弧只取圆心距）。解析评价器
用真实弧与真实切线，因此：

* 256 的最小交叉角 34.92°（原版 35.0°，论文一致）；
* 512 的最小交叉角 **23.07°**（原版 14.0°）。以解析最小角对应的那一对为例：
  路线 178（竖直线段）与路线 347（R5 圆弧）在 (123.45, 104.33) 相交，该点处弧的
  切线与竖直方向夹角为 23.07° —— 位置同时落在两条曲线上（用弧的解析方程验证），
  角度由真实切线算出。原版的 14° 出自弦近似与边界分支，不是该点的真实切线角；
* 事件数：512 原版逐路记录 86512 条（168.97/路），解析 86786 条（169.5/路），
  解析多检出约 137 个唯一事件（弦近似把部分弧上交叉判到了弦外）。

因此**对照使用解析口径**；原版口径仅作参考，两者的差异属于近似方式差异，
不是布线几何差异。

### 9.3 固定两弯结构是不可突破的上限

所有方案的弯曲个数都是每路 2 个、总弯角恒为 180°（或由 `dx<2R` 决定的 2θ）。
在"不许改变路径拓扑"的约束下，唯一可调的是轨道位置与半径，而 8.2 节说明轨道位置
对损耗几乎没有杠杆。**如果目标是显著降低平均/最坏损耗，下一步应该允许改变路径
结构**（例如三弯/多弯的绕行、非均匀半径组合），而不是继续在轨道选择上搜索 ——
但那已经超出"原版几何约束下重布线"的范围，需要单独论证制造可行性。

### 9.4 其他已知限制

* 交叉损耗表是论文图 3-12 的数字化近似（原版运行时用的外部工作簿从未随 EXE 发布，
  本地也不存在），绝对值不可信、形状可用；本实验所有对照都用同一张表，未通过
  更换表制造收益。角度按原版 `int()` 截断查询（<1° 时按表中最小的 1° 处理，
  实际数据未触发）。
* 间距阈值（线宽 + 标称间隔）是实验假设，只保证"不劣于原版轨道栅格的标称值"，
  不代表制造规范；A 自身就有 393（256）/ 692（512）个近并行间距不足，
  说明**原版几何本来就不满足这一假设**。
* 消融里带未布通路线的配置（跨度/拥塞优先、penalty=0）只是诊断，不能与完整方案
  直接比较平均损耗。
* 方案 D 的半径候选只有 R5/R6 两档（已有实测弯曲损耗数据的档位）；R4/R8 等
  没有进入首版候选。

## 10. 复现命令

本实验**没有使用任何随机策略**：候选枚举、排序、评分、拆线重布与半径选择全部是
确定性的（排序键含扫描顺序与轨道坐标，不含随机数），因此不需要记录种子；
同一环境重复运行会得到逐位相同的产物。

```powershell
# 全套 A/B/C/D + 消融（256 与 512）
..\OpticalWaveguideRouter2D\.venv\Scripts\python.exe -B scripts\opt2d_run_all.py --channels 256 512

# 只重画图（用已保存的逐路 CSV）
..\OpticalWaveguideRouter2D\.venv\Scripts\python.exe -B scripts\opt2d_run_all.py --channels 512 --figures-only

# opt2d 验收测试（含原版回归、逐路计入、异半径求交、失败回滚、交叉点自洽）
..\OpticalWaveguideRouter2D\.venv\Scripts\python.exe -m pytest tests\test_opt2d.py -q
```

产物：

```text
outputs/opt2d/<channels>/
  A|B|C|D/            per_route.csv、summary.json、crossing_events.csv、spacing_events.csv
  sensitivity/        各消融配置的同样产物
  comparison.csv/.json A/B/C/D 对照表
  sensitivity.json     消融汇总
  figures/            损耗分布、损耗分解、指标对比、各方案最差路线局部图
```
