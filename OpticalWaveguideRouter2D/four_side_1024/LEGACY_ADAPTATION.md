# 原逆向算法的 1024 通道四边适配边界

本适配以原逆向 AutoRouter 的轨道排布方式为基础：按固定次序处理路线，沿一个固定方向扫描轨道，选择第一个满足 `noCross` 风格轨道约束与全局单层几何检查的轨道。它只扩展处理四边和每接头 32 通道所需的接口。原有 256/512 函数仍保留原接口与限制，不宣称它们未经修改便能直接处理 1024 四边输入。

本适配入口为 `legacy_adapter.py`，结果单独写入 `outputs/four_side_1024_legacy_single_layer_v1/`。先前通用候选搜索的代码及输出保留以供追溯；它们不是本适配的路由入口。

当前约束：邻边保留固定 L 形／三弯模板，保留总运行时间和总几何评价预算；取消每条路线256次评价上限。可用轨道自然有限，逐轨处理至找到合法路径、轨道用尽或全局预算用尽。

跨边分支按固定坐标方向分别调用：N/W源边使用 `above2below`，E/S源边使用 `below2above`，本CSV各分配512条。前者使用上下节点角色互换和 `y_rule=150-y_geometry`，按规则坐标升序；后者按规则坐标降序。两分支保留各自原端口次序条件，不能用两个谓词取“或”来放宽规则。该输入没有同边连接，原 `below`、`above` 同边分支仍在旧代码中保留，不强套到跨边连接。

直接 L 接口的精确转弯位置纳入该组轨道状态表，避免使用邻近网格坐标进行规则检查。基本轨道步进仍为0.175 mm，新增位置仅用于固定端口的L接口状态。

默认入口仅准备输入；一次布线的显式命令为 `.venv/Scripts/python.exe -m four_side_1024.legacy_adapter --route --seconds 600 --evaluations 900000`。这两个预算均为全局预算，不再另设每条评价上限。历史66条输出是修改前的实验结果，不能当作此版本的布通率。

## 必要差异

| 部分 | 原逆向算法 | 四边适配的必要处理 |
|---|---|---|
| 接头坐标 | 上下双边坐标及双边索引 | 保留 CSV 身份，将 N/S/E/W 转换到局部布线坐标，完成后逆变换回全局 x/y |
| 端口方向 | 双边出入射方向 | 对边采用对应的旋转；邻边还需处理端口方向相差 90° 的接口 |
| 接头通道数 | 接头数组及索引含 16 通道假设 | 在独立适配器内参数化为 32 通道，仍保留 CSV 的 row、column、channel 信息 |
| 轨道调度 | 扫描轨道并取第一个可用轨道 | 同一固定顺序与单调扫描；失败后记录失败，不另启多策略竞争或拆线重布 |
| `noCross` 上下文 | 上下双边的局部接头、轨道、相对次序 | 对四边坐标和32通道索引作必要适配；再由同一个全局索引检验全部路线 |
| 圆弧几何 | 由原圆弧公式按位移构造 | 对边使用同一半径和小位移关系；邻边增加90°方向接口，不以新路径族替换轨道算法 |
| 同层冲突 | 双边数据结构中的既有检查 | 六类边对统一进入一个 layer=0 冲突索引，两排通道共同检测 |

刚体旋转不改变夹角，不能把邻边相差 90° 的出入射方向变成对边的方向关系。因此邻边接口是实际新增的必要几何适配，不能描述成“只转一下原函数就完全不变”。原 `noCross` 中依赖上下接头索引、`ln_calc`、`sn_calc` 和局部次序的部分也不能直接套到任意边对；相应适配需在代码中明确，而不能声称原谓词原封不动已适用于全部四边组合。

## 原小位移圆弧公式与固定半径

令对边路线在局部坐标中的横向位移绝对值为 d，配置弯曲半径为 R。原 `wiring_bend_826.py` 在 `0 < d < 2R` 时采用：

```text
theta = arccos((R - d/2) / R)
longitudinal_offset = R * sin(theta)
```

这里每段圆弧的半径仍是 R。位移变小时，弧的转角和投影缩短，半径不变；不能用 `R=d/2` 代替，也不能因空间不足悄悄减小 R。d 不小于 2R 时，原90°圆弧与剩余直线按原半径构造；d 为零时可退化为与端口方向一致的直线。方向符号和弧的起止角由局部方向确定，最终须通过端点、切向、连续性、半径及板界检查。

本次 R 的初始值为5 mm。邻边90°圆弧也受同一下限约束。旧公式并不保证任意固定端点和轨道都有足够的切向长度，空间不够时必须拒绝该轨道并继续单调扫描，耗尽可用轨道或预算后记录失败。

## 不允许改变的输入与调度边界

CSV 必须完整读取。`route_id`、源目标接头、行、列、通道以及配对保持一致，不通过交换目标端点或重新分组修正局部顺序。原算法按端口次序整理轨道的做法，只能在保持源目标身份和坐标不变的前提下适配；不能把交换配对包装成“重排”。

本适配只使用一种确定的路线次序和 first-free 单调轨道扫描，不调用通用 `router.py` 中的 Dubins 候选、内部姿态绕行、多调度策略比较或 Rip-up and Reroute。为轨道是否合格而进行的几何检测不是新增的全局优化算法。若原轨道规则拒绝路线，不会换一种路由器来补齐，再把结果称作原算法适配。

板面固定为150 × 150 mm。所有成功路线均为 layer=0，row=1 和 row=2 仍是同一接头的两排通道；对边与邻边、上下与左右全部共同进行冲突检测。不得把独立的局部轨道编号当成独立的物理层。允许并记录的同层交叉须通过同一规则检查，其余位置仍检查重叠、自交及波导间距。

## 物理和结论限制

适配仍明确使用 `virtual_unfolded` 计算端点，同时保留真实2×16接头面行列坐标。原接头面双排到单层计算端点的物理耦合未由轨道适配解决。暂定9 mm接头中心距与完整 MPO 外框套的机械冲突也必须保留在报告中，不能因沿用旧算法而忽略。半径、宽度和间距是初版验证参数，旧损耗模型仅作对照估计。

失败意味着该确定顺序、单调轨道集合及预算中没有找到合格轨道，不是所有可能二维曲线都不可能布通的证明。成功数量、交叉和几何检查必须来自此独立入口的真实运行，不能引用先前通用搜索实验的数字。结果即使通过计算几何检查，也不直接构成接头装配、展开耦合器或玻璃同层交叉工艺的制造验收。
