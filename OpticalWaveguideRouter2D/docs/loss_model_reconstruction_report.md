# 原版 AutoRouter 损耗模型复刻报告

对象：`OpticalWaveguideRouter2D` 的损耗链复刻，对照《面向板级高速光互连应用的光波导智能排布技术研究》（黄志杰，上海交通大学学士学位论文，2020 年 6 月，下文简称"论文"）。

本轮**不修改 routing 算法**。复刻后 `tools/exact_fidelity_gate.py` 仍为 **512/512 exact**，冻结分组 `above->above 112/112`、`below->above 115/115` 未下降。

---

## 1. 论文损耗模型

论文 3.3.2 节（印刷第 19 页）把单根波导的总损耗拆成三项：

> 波导损耗分为三部分计算，分别为直波导固有损耗，波导弯曲损耗和波导交叉带来额外的插入损耗。

并在式 3-19 给出总损耗：

```
Lt = Lb × 2 + L0 × ls + Σ Lc        (3-19)
```

- `Lt`：单根波导总损耗
- `Lb`：单个波导弯曲损耗
- `L0`：直波导损耗（单位长度）
- `ls`：直波导部分总长度
- `Lc`：波导交叉带来的插入损耗

论文 3.1.5 节说明为什么是 `Lb × 2`：第一类 U 形与第二类 Z 形波导由**三段直波导 + 两段 90° 弯曲**组成，第三类 Z 形由**两段直波导 + 两段小于 90° 的弯曲**组成，且

> 起始端的波导弯曲和终止端的波导弯曲总是对称存在。

因此每根波导恰好两个弯曲，`2 × Lb` 成立。

## 2. 论文公式

| 式号 | 内容 | 出处 |
| --- | --- | --- |
| 3-7 | `θ = arccos((r - dx/2) / r)`，`dx < 2r` 时的弯曲角度 | 论文 3.1.5，印刷 p12 |
| 3-16 | `α = arccos(l / r)`，直波导与圆弧交叉时的锐角，`l` 为直波导线到弯曲圆心的距离 | 论文 3.3.1，印刷 p18–19 |
| 3-17 | `α = arccos((2r² - lc²) / (2r²))`，圆弧与圆弧交叉，`lc` 为两圆心距离 | 论文 3.3.1，印刷 p19 |
| 3-18 | `Lb = L90 × θ / 90°`，`θ` 采用角度制 | 论文 3.3.2，印刷 p19 |
| 3-19 | `Lt = Lb × 2 + L0 × ls + Σ Lc` | 论文 3.3.2，印刷 p19 |

论文 3.3.2 还明确了一条去重规则：

> 由于算法遍历所有的直波导，因此每一个交叉都被实际计算了两次，在进行统计工作时需要根据相互交叉的两根波导的编号对每一个交叉进行标记，剔除相同的交叉。

这一点在下文第 6、7 节有重要后果。

## 3. 直波导损耗

论文表 2-1（印刷 p7）给出**直波导损耗 0.05 dB/cm**，即

```python
straight_loss_db = straight_length_cm * 0.05
```

几何内部单位是 **mm**（`plotter_bend` 写出的 `inflection_x`、`bend_x`、`center`、`theta` 均以 mm 与弧度为单位，布线区域为 150 mm × 150 mm），换算：

```python
straight_loss_db = straight_length_mm / 10.0 * 0.05   # = mm * 0.005
```

原版 `calc_loss` 内部的 `straight_loss = -0.005` 正是这个系数的 dB/mm 形式，两者一致。

**`ls` 只算直线部分。** 原版 `calc_length` 返回的是**含弧长的总几何长度**，因此本复刻显式区分：

- `straight_length_mm = total_length_mm - arc_length_mm`
- `bend_arc_length_mm = Σ (θ_end - θ_start) × R`（`theta` 为弧度区间）

两者相加即 `total_length_mm`。第 8 节说明为什么这样不会把弧长算两遍。

## 4. 弯曲损耗

论文表 3-1（印刷 p19）给出不同半径下 90° 波导弯曲损耗，数据来源于实验室实测：

| 弯曲半径 | 损耗 |
| --- | --- |
| 2 mm | 7.94 dB |
| 3 mm | 6.81 dB |
| 4 mm | 4.59 dB |
| 5 mm | 2.39 dB |
| 6 mm | 1.90 dB |

**这张表就是本轮最重要的发现之一：它是原版程序内部两张表相除的结果，不是独立数据。**

原版 `calc_loss` 内硬编码：

```python
r  = [2, 3, 4, 5, 6, 8, 10, 15]
tl = [-16.0, -10.59, -6.08, -2.8, -2.03, -1.39, -0.87, -0.45]
ll = [6.33, 7.33, 8.33, 9.23, 10.05, 11.53, 12.92, 15.74]
bend_loss = tl[i] / ll[i]          # 弯曲损耗密度，dB/mm
```

`tl` 是实验室在参考长度 `ll` 上测得的总损耗（负号是因为原程序累加的是**透过率**而非损耗）。用密度乘上 90° 弧长 `R·π/2`：

| R | `tl/ll` (dB/mm) | `R·π/2 × 密度` | 论文表 3-1 |
| ---: | ---: | ---: | ---: |
| 2 | 2.527646 | **7.9408** | 7.94 |
| 3 | 1.444748 | **6.8082** | 6.81 |
| 4 | 0.729892 | **4.5860** | 4.59 |
| 5 | 0.303359 | **2.3826** | 2.39 |
| 6 | 0.201990 | **1.9037** | 1.90 |

五位全部吻合到论文的两位小数——表 3-1 是这批原始数据的四舍五入。因此复刻实现的是**原始密度**（`2.3826`），而不是论文印出的 `2.39`；论文的 45° 值 `1.195` 同理对应模型的 `1.1913`。

非 90° 弯曲按式 3-18 线性换算。原版实现的是等价的弧长形式：

```
弧长 × 密度 = R·θ_rad × 密度 = (R·π/2 × 密度) × θ_deg/90 = L90 × θ/90
```

两者**恒等**（`tools` 与测试中均有断言），所以按 `theta` 弧度区间积分与按 `Lb = L90 × θ/90°` 求和给出完全相同的结果。

`theta` 在原版工作簿里存的是**弧度区间**（例如 `[(0, 1.5707…), (1.5707…, 3.1415…)]`，即两段 90°），复刻中不把它当角度使用。

## 5. 交叉检测

原版 `calc_crossing` 逐条波导建立折线段列表，再遍历 `data[["inflection_x", "inflection_y", "center"]]` 的每一行做线段求交（`is_cross` + `is_fall_on`），对每个交叉点按位置分派到三类角度计算：

- **直—直交叉**：默认 90°，即字典键 `0` 对应 `90`
- **直—圆弧交叉**：`line_to_arc`，即式 3-16 `α = arccos(d / r)`，`d` 为直波导线到圆心距离
- **圆弧—圆弧交叉**：`arc_to_arc`，即式 3-17 `α = arccos(1 - d² / (2r²))`，`d` 为两圆心距离

`f()` 用交叉点落在哪一段（`is_across_at_bend` 返回 −7…7）选择正确的圆心与直线，细节保持原版。

**关于"原版交叉分析是 DEBUG-only"的旧结论已被推翻。** 反编译器 decompyle3 把 `calc_crossing` 的整个函数体错误地缩进到了 `DEBUG` 门内，使非调试路径落出函数末尾返回 `None`，看起来像"非 DEBUG 下不做交叉分析"。反汇编原始字节码后可以看到真实结构：

```
 58  L130  LOAD_GLOBAL  os; ... COMPARE_OP == 'True'
 70  L130  POP_JUMP_IF_FALSE 86      ; 非 DEBUG -> 86（跳过下面的提前返回）
 72  L130  row.name != 56
 80  L130  POP_JUMP_IF_FALSE 86
 82  L131  BUILD_LIST 0
 84  L131  RETURN_VALUE              ; 只有这个 return [] 受 DEBUG 门控制
 86  L133  BUILD_LIST 0 / STORE_DEREF lines
 ...                                 ; lines / points / count / min_angle
278  L147  LOAD_FAST points
280  L147  RETURN_VALUE              ; 正常路径返回 points
```

即 `DEBUG` 门只包住"非 56 号路由直接返回空列表"这一个提前返回，其余逻辑在函数层级执行。本轮已按字节码恢复为扁平结构（第 8 节）。

## 6. 交叉损耗来源

### 6.1 原版数据：本地不存在

原版 `calc_loss` 从**外部传入**的 DataFrame 取交叉损耗：

```python
l += loss.loc[loss["angle"] == int(a)]["loss_db"].values[0] / 30
```

表需要 `angle`（整数角度）与 `loss_db`（**30 个交叉**的插入损耗）两列；除以 30 得单次交叉损耗。这份表**没有随 EXE 发布**。本轮做了穷尽搜索：

| 搜索位置 | 结果 |
| --- | --- |
| `PYZ-00.pyz` 解包后的全部条目 | 只有 5 个业务模块（`main`/`problem_graph`/`waveguide_calculator`/`wiring_rect_826`/`wiring_bend_826`），无数据文件 |
| `AutoRouter.exe` 二进制本体 | 无 `PK\x03\x04`、无 `.xlsx`、无 `loss_db` 字节序列 |
| `AutoRouter.zip` / `自动排布.zip` | 仅 `fiberBoard256.xlsx`、`fiberBoard512.xlsx` 与 matplotlib 示例 CSV |
| 整个 `Graduation Project` 目录的 `*.xlsx/*.xls/*.csv` | 无任何含 `angle`/`loss_db` 列的文件 |
| 反编译源码与解包目录 | `loss_db` 只出现在 `waveguide_calculator.py` 的被调用处，没有定义处 |

`main.py` 也从未调用 `calc_index`（只 import），所以打包时不存在这张表。

**结论：原版 crossing loss 表在本机不可得。**

### 6.2 采用的数据：论文图 3-12 数字化 + 论文文字锚定

论文 3.3.2 说不同角度的交叉插入损耗"通过仿真得到"，并给出图 3-12《不同交叉角度和交叉数量下波导的接收功率》，图例为 `cross number 10 / 20 / 30`，横轴角度 0–180°，纵轴归一化接收功率（dB）。**"cross number 30"曲线的纵轴值正是 `loss_db` 列的含义**（30 个交叉的插入损耗），也与论文文字吻合：

> 在交叉角度为 90° 时，30 个交叉波导带来的额外插入损耗约为 0.05 dB。

据此生成 `data/crossing_loss_from_thesis_fig3_12.csv`（180 行，`angle_deg, loss_db_per_30_crossings`）：

- **来源**：论文图 3-12（印刷 p20）嵌入的原始 PNG（973×601）
- **方法**：`tools/digitize_fig3_12.py` 按网格标定（0°→x≈125.5 px，180°→x≈805.5 px；0 dB→y=51，−1 dB→y=523），按颜色提取 `cross number 30` 绿线，每个整数角度取 ±2 px 窗口内绿线像素纵坐标的**中位数**，再折算为 dB
- **误差**：像素标定精度约 0.01 dB；但**原图曲线本身抖动幅度约 0.1 dB**，远大于单次交叉损耗（0.05/30 = 0.0017 dB），因此只有**趋势**可信、绝对高度不可信
- **锚定**：数字化得到的 90° 值为 0.0593 dB，与论文文字的 0.05 dB 差约 18%。`loss_model.load_crossing_table` 因此把整条曲线按 `0.05 / 0.0593` 缩放，使 90° 精确等于论文给出的 0.05 dB——用论文的精确文字值消除像素标定的系统偏移，形状仍全部来自图 3-12

**这是 approximation，不是原版仿真数据。** 代码与报告中所有出现处均已标注。

### 6.3 单次 90° 交叉的 sanity check

论文文字给出的 `0.05 dB / 30 = 0.001667 dB` 仅用作量级校核，未被当作所有角度的常数；模型对每个角度使用表中对应的值。

## 7. 原版 AutoRouter 实现

把 `calc_loss` 的字节码逐条对齐后，原版公式为（符号沿用原版，累加的是透过率故为负）：

```
acc  = Σ_crossings  loss_db[angle] / 30
acc += Σ_theta      (θ₁ - θ₀) · R · (bend_density - straight_density)
acc += length · straight_density
```

其中 `bend_density = tl/ll`、`straight_density = -0.005`，`length` 为含弧长的**总**几何长度。展开后两项：

```
Σ_theta (θ₁-θ₀)·R·bend_density + length·straight_density - Σ_theta (θ₁-θ₀)·R·straight_density
= Σ_arc (arc · bend_density) + (length - arc_length) · straight_density
= Σ Lb + L0 · ls
```

**恰好就是论文式 3-19**。也就是说：原版 `waveguide_calculator.py` **实现了论文的损耗模型**，而且没有把弧长计入 `L0·ls`。

需要强调的三点：

1. **符号约定（隐含且关键）**：原版所有量都用"负 = 有损耗"的约定——`tl` 是负的（`-2.8`），`straight_loss = -0.005`，因此**传入的 `loss_db` 列也必须是负值**。原版代码写的是 `l += loss.loc[...]["loss_db"].values[0] / 30`，直接相加而未取负，只有在列值为负时交叉才真正**增加**损耗。

   这一点可以独立验证：512 通道 R = 5 mm 用同一张表，把交叉项按"减去"处理得到平均 **4.87 dB**，按"加上"处理得到 **5.51 dB**；论文报告的是 **5.5 dB**。因此原版表值为负，复刻实现的是"减去正损耗表"这一等价形式（`legacy_signed_loss` 中 `acc -= crossing_loss_db(...)`），两条代码路径的逐路由结果差异不超过 1.8e-15 dB。

2. **符号方向**：原版 `loss` 列是负数（累加透过率）。`draw_chart` 里 `-float(x.loss)` 才翻成损耗。本复刻保留该符号，使 `calc_index` 的 `loss` 列仍可逐位对照原始字节码；`loss_model` 另行给出正的 dB。

3. **交叉不去重**：`calc_crossing` 让每条波导与其他所有波导求交，因此每个物理交叉被计入两次，而 `calc_loss` 对 `x.angles` 里每一项都累加一次，**没有按波导编号去重**。这与论文 3.3.1 节"剔除相同的交叉"的文字描述不符。第 9–12 节说明：**论文报告的数值来自不去重的累加**。

三个 case 的六个数字**全部落在论文印刷精度（一位小数）以内或边缘**，最大相对误差 1.05%。

### 12.1 512 R5 的损耗分量贡献

| 分量 | 平均 (dB) | 占总损耗 |
| --- | ---: | ---: |
| 弯曲损耗 `Σ Lb` | 4.5587 | **82.7%** |

| 交叉损耗 `Σ Lc` | 0.3205 | 5.8% |

论文全文总结的判断是"弯曲半径/弯曲损耗起主导作用，长度其次，交叉数量影响较弱"。**数据支持这个结论**：弯曲占 82.7%，直波导 11.5%，交叉仅 5.8%。256 通道（85.7% / 11.8% / 2.5%）与 R = 4 mm（90.2% / 6.7% / 3.1%）方向一致。

需要指出：论文 4.4 节还提到另一种口径——交叉角度低于 20° 时估算偏差较大，而低角度交叉正是交叉项中权重较高的部分，因此 5.8% 这个份额的不确定度主要来自交叉项本身。

### 13.2 论文 4.2 节的单位笔误

论文 4.2 节（印刷 p23）原文：

> 256 通道波导排布的波导间距为 **250 µm**，波导宽度仍为 **50 µm**，每个 PMT 仍拥有 16 根波导，PMT 宽度可由式 4-1 计算得到，256 通道波导排布的 PMT 宽度为 **4.8 µm** …… 对于 256 通道排布，**150 µm** 的布线区域宽度足以满足上下 PMT 弯曲错位的需求 …… 本文采用 PMT 间距为 **4.2 µm**。

其中三处单位应为 **mm**：

- PMT 宽度：由式 4-1 `W = (w + d) × P = (0.05 + 0.25) × 16 = 4.8 mm`，与论文同时印出的 "4.8" 数值自洽，故为 mm
- PMT 间距 4.2：与 4.1 节 512 通道的"PMT 间距为 1.7 mm"同类量级，应为 mm
- 布线区域"150 µm"：论文全局布线区域为 150 mm × 150 mm，应为 mm

**thesis text appears inconsistent here.** 本报告按记录原值、不做静默修正的原则处理：复刻使用的是 250 µm 间距与 150 mm 区域（由 `data/fiberBoard256.xlsx` 与算法参数一致确定），与论文 4.2 的数值部分自洽。

### 13.3 全文总结中的文字矛盾

论文全文总结（印刷 p28）原文：

> 通过对比不同通道数量和不同弯曲半径的波导排布结果，得出**弯曲半径越大则波导排布整体损耗越大**，且波导弯曲半径对波导排布整体损耗的影响最大的结论。

The thesis contains an apparent textual contradiction. The numerical table and experiments support: **larger radius → lower bend loss.** 依据：

- 表 3-1：R = 2 mm → 7.94 dB，R = 5 mm → 2.39 dB，R = 6 mm → 1.90 dB，半径越大损耗越小
- 论文 4.3 节：R = 4 mm 平均 9.8 dB > R = 5 mm 平均 5.5 dB
- 本轮独立复现：R = 2 → 16.59 dB，R = 3 → 14.23 dB，R = 4 → 9.81 dB，R = 5 → 5.51 dB，单调递减
- **同一段的另一句与之直接冲突**："这种影响可以通过**增大**波导弯曲半径以缓解，同时可以**减小**波导弯曲部分带来的损耗"

本报告不代论文改写，仅记录该矛盾。
