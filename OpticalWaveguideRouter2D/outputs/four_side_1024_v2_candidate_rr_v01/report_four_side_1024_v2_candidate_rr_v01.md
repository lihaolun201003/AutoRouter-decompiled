# 1024 通道四边 D56 布线 V2 双高度优化轮：扩大候选搜索与强化拆线重布（R≥40 mm / 30 µm 边缘间距）

本报告对应代码包 `OpticalWaveguideRouter2D/four_side_1024/v2opt/`（本轮新增）以及冻结复用的
`four_side_1024/fslw/`、`four_side_1024/d56/`；交付目录
`OpticalWaveguideRouter2D/outputs/four_side_1024_v2_candidate_rr_v01/`。
本轮全部数字来自本机真实运行 + 两套独立几何实现（路由器 `d56/index.py` 的 exact strict 索引、
独立权威校验器 `fslw/validate_fslw.py`），未用任何历史数字冒充实测。

**与上一轮的关系：** 上一轮 `outputs/four_side_1024_fslw_R40_gap30_abcd/`（真实 2×16 双高度接口、
R=40 mm、30 µm 边缘间距、ABCD 四种策略）原样保留；本轮**不研究 V3、不改变物理模型、不改变 V2
连接配对**，只优化既有 D56 的搜索与调度。上一轮最佳单组为 V2-C 694/1024；本轮先把 z1（V2-D 492）
+ z2（V2-C 206）两个独立平面重新组合，经独立严格验收后得到 **698/1024** 正式基线。

## 1. 结论摘要

| 指标 | 结果 |
|---|---|
| 上一轮最佳单组 | V2-C 694/1024（67.77%） |
| **698 组合基线**（z1=V2-D 492 + z2=V2-C 206） | **698/1024（68.16%）**，独立 strict 验收通过 |
| z2 候选预算对照（冻结 206 布局，独立插入） | 200→22 条、400→42、800→62、1600→62（**800 饱和**） |
| z2 E1（扩大候选、无强化 R&R） | 206 → **243/512**（+37） |
| z2 E2（原预算 200 + 强化 R&R） | 206 → **209/512**（+3，2 轮后饱和） |
| z2 E3（扩大候选 + 强化 R&R） | 206 → **244/512**（+38；其中 R&R 首轮早停仅 +1） |
| z2 E3X（E3 续跑：更大 R&R 搜索预算，延伸实验） | 244 → **244/512（+0）**，4 轮、k=1..8，无任何净增益事务 |
| z1 Z1OPT（扩大候选 + 强化 R&R） | 492 → **508/512**（+16；R&R 贡献 13） |
| **本轮最优 1024 组合（BEST）** | **z1 508 + z2 244 = 752/1024 = 73.44%**（比 698 基线 +54） |
| 全部新成功路线 strict 验收 | 两平面 `validate_fslw --policy strict` passed=True、violations=0 |


核心结论：

1. **698 组合基线成立且可复验**，比上一轮最佳单组高 4 条、比上一轮全部 8 组结果都高；
   本轮最终 **BEST = 752/1024（73.44%）**（z1 508 + z2 244），全部通过独立 strict 验收。
2. **z2 的低布通率不是"全局搜索预算不足"造成的**：把候选预算从 200 提到 800 确实能多救回
   40 条（22→62），但 800→1600 边际收益为 **0**，说明当前 D56 候选生成器的**候选空间**（而非
   评价预算）已经先饱和；再增加预算没有意义。
3. **z2 的主要瓶颈是"已布路线造成的拥塞与顺序耦合"**：冻结布局下可独立插入的 62 条路线，
   贪心顺序提交只布进 37 条（59.7%），另 25 条被先布入的路线挡住；剩余 244 条失败中 202 条
   是"有合法候选但被占位阻挡"，且阻挡高度集中在少数路线上（Top-15 blocker 占总阻挡命中 40%）。
4. **R&R 在 z2 稠密布局上收益有限且已饱和**（原预算 +3、扩大候选 +1；E3X 以 k=1..12 + extras +
   并行事务 + 4 轮扩展搜索仍 **0 增益**），但在 **z1 上非常有效**（+13 条），说明 R&R 是否有效
   强烈依赖"被拆路线能否重布"这一结构条件。
5. **128 条历史"无候选"角部路线是本轮最硬的几何墙**：扩展候选库（同 primitive 集）下
   86/128 在空板能生成合法候选（仅来自 Z5/DOWN_LOOP），但冻结布局下 0/128 可插入；
   42/128 在当前候选库下**生成不出任何合法几何**（独立随机探针 20k/线 + 42 条各 100k 延长尝试，
   合计约 510 万次枚举仍 0 发现）。这与"候选预算/布局"无关，属固定端口切向 + R=40 + 150 mm 板 +
   禁止自交带来的 D56 可达性限制（证据边界见第 5.2、11 节）。
6. 最终建议（详见第 7 节）：**二维 D56 的搜索/调度已接近其收益上限（本轮实测上限 752/1024；
   乐观估计继续调优最多约 768~788/1024，即 75%~77%），不建议继续主要投入 D56 二维调优；
   应在完成本轮基线收尾后，启动原生 Native 3D 联合寻路的前置研究（接口 z 向过渡方式）**，
   同时保留 D56 2D 作为对照基线。

## 3. 基线：历史结果重组与独立验收（698/1024）

### 3.1 组合规则

上一轮 z1、z2 是两个**独立二维问题**（z1 = CSV row1 对边 NS/EW；z2 = CSV row2 邻边
EN/ES/SW/NW；z=0.0/0.5 mm 两个高度），跨平面 XY 投影交叉不是同层冲突。因此可逐平面取历史最优：

| 平面 | 历史来源 | routed | strict 审计 |
|---|---|---:|---|
| z1 | `planes/V2/D/z1/routes.json`（算法 D，联合 LNS） | 492/512 | PASS |
| z2 | `planes/V2/C/z2/routes.json`（算法 C，四边轮转） | 206/512 | PASS |
| **组合基线** | 两平面独立 2D、z 不同高度 | **698/1024 = 68.16%** | PASS |

698 比上一轮最佳单组 V2-C（694/1024）高 4 条，比上一轮四组 V2 结果
（A 681 / B 677 / C 694 / D 638）都高。

### 3.2 独立验收过程与证据

`four_side_1024/v2opt/audit_baseline.py`（可幂等重跑，约 51 s）：

1. 从历史 `routes.json` 读入两条平面 512 条记录，保留 routed 路线的**真实 primitive 链**；
2. 用 `fslw.ports.load_plane('V2', plane)` 的 CSV 端口表逐条比对 route_id / source_endpoint /
   target_endpoint / pair / relation / side / row（9 字段）→ 0 mismatch；routed primitives
   与历史文件深度相等（deep-equal）且 canonical 字节相等；
3. `validate_fslw.build_report(policy='strict', expected_route_count=512)`：
   z1 passed=True, crossings=66775；z2 passed=True, crossings=7020；violations=0、d56_failed=0；
4. 用 `d56.index.D56Index(w=0.05, gap=0.03, strict)` 独立重建两个平面布局、逐条 leave-one-out
   自检 → 492/492、206/206 全部有效；`fslw.crosscheck_fslw` 全对比较 mismatch=0（交叉计数与
   独立校验器一致）；

   `layer_2d.png`/`overlay_3d.png` 生成。

证据文件：`baseline_acceptance.json`（7 项逐条证据 + 16 个产物 sha256）、
`planes/V2/BASE/{z1,z2}/audit_strict.json`、`combined/V2/BASE/`。

## 4. 方法：扩大 D56 候选搜索与强化 R&R

方法细节见 `four_side_1024/v2opt/METHOD.md`。

### 4.1 为什么不能只调大预算

上一轮 z2 的 178 条 `no_legal_candidate` 中 **175 条恰好停在 200 次候选评价**，但历史生成器
对邻边路线最多只能产出约 200~240 条不同候选（深层 Z3 24×24 采样 + 浅/深层截断），因此
200→400→800→1600 单纯加预算没有意义。必须**先扩展候选队列的数量与多样性**，预算才是有效变量。
本轮先用第 5.1 节的独立插入实验验证了这一点（800→1600 收益为 0）。

### 4.2 候选扩展（同一 primitive 集）

`v2opt/candext.py` 在冻结的 D56 primitive 集内扩展搜索：

| 方面 | 上一轮 | 本轮 |
|---|---|---|
| 轨道采样 | 固定 24 点粗网格 / 结构值 | 由当前已布几何推导的 clearance tracks（贴 0.08 mm 净空）+ 结构坐标，池 600/轴 |
| 路径族 | L / TURN_S / SHIFT_TURN / Z3 / LEFT / Z5 | 上述冻结族 + 新 `DOWN_LOOP`（左-上-右下的长 staircase，支持从上方以 +x 切向进入 q，带短 S 高度修正） |
| 队列容量 | 邻边 ≤ ~240 条 | 邻边 300~6000 条（按路线几何），四档预算评价同一排序队列的前缀 |
| 排序 | cheap 平行占用分 | 平行占用 + 横向穿越数加权 + 按族 round-robin 交错 + 确定性 per-route 抖动 |
| 去重 | 无 | primitive 链签名去重（同几何只评价一次，不同几何不误删） |
| 缓存 | 无 | 每路线 spec 列表缓存（R&R 反复尝试时只重新打分/构建） |

所有候选仍由 `fslw.geom` 的构造函数与 `canonical_validate` 预检（端点、切向、R=40、板界、自交）；
合法性最终由 `d56/index.py` exact strict 索引判定。

### 4.3 强化拆线重布（R&R）

`v2opt/rr.py`：

1. **重新计算阻挡关系**：每轮对失败路线在当前布局上重新尝试（并行 worker + 协调进程重验提交），
   得到最新 blockers，不沿用上一轮旧统计；
2. **按阻挡影响选拆线对象**：统计每条已布路线阻挡多少失败路线、被引用次数，加权抽样 blocker 组；
3. **拆线规模** k ∈ {1,2,4,8,12}（任务要求 2/4/8/12，k=1 作对照）；E3X 延伸实验按轮升级 k；
4. **多种重布顺序**：ripped_first / target_first / reversed / random / congestion_desc / congestion_asc；
5. **并行事务**：每轮把事务分发到多进程，各自在快照上"拆线→布目标→重布被拆路线"；事务可附带
   extras（被同一批 blocker 阻挡的其他失败路线），允许"净增 >1、少回插 1 条仍盈利"；
6. **提交前重验 + 严格 best-so-far**：协调进程对每个事务的每条 placement 在当前布局上重新
   `index.evaluate`；任何一条不合法或 routed 数不增加 → 完整回滚（accepted 与 failed 状态
   一并恢复），只有严格增加才提交（回归测试第 4/6 条覆盖）；
7. **预算与可恢复性**：事务数/评价数/墙钟/轮数上限；每轮 checkpoint 记录真实 primitive 链，
   中断可从最近 checkpoint 恢复。

### 4.4 消融设计

三组实验都以**经过独立验收的 698 组合基线**为初始解，物理约束相同：

| 实验 | 候选搜索 | R&R |
|---|---|---|
| E1 | 扩大（1600 评价/路线 + 扩展候选队列） | 不做强化 R&R（一次贪心顺序插入） |
| E2 | 原预算（200 评价/路线 + 历史生成器） | 强化 R&R |
| E3 | 扩大（同 E1） | 强化 R&R |

重点先 z2；z2 有结论后对 z1 的 20 条失败路线做同样处理（Z1OPT）。

## 5. z2 平面实验结果

### 5.1 候选预算对照（任务 5.1/5.4）

保持 z2 基线 206 条成功路线**不变**，把 306 条失败路线逐条放回当前布局中独立测试
（`v2opt/search.py:parallel_sweep`，10 进程并行，找到不提交），四档预算结果：

| 每路线评价预算 | 可直接插入条数 | 边际新增 | 评价次数合计 | 耗时 s |
|---:|---:|---:|---:|---:|
| 200（原基线） | 22 | — | 36,057 | 106.1 |
| 400 | 42 | +20 | 58,686 | 170.8 |
| 800 | 62 | +20 | 81,821 | 197.5 |
| 1600 | 62 | **+0（饱和）** | 90,851 | 194.7 |

关键事实：

1. **200→800 有效、800→1600 无效**：成功候选在队列中的位置中位 234、最大 778，全部 <800；
   即当前 D56 扩展候选生成器的候选空间在 800 附近耗罄。**继续加大评价预算没有收益。**
2. 救回的 62 条全部来自上一轮 `no_legal_candidate`（预算耗尽）组：62/178 = **34.8%**；
   上一轮 128 条 `no_candidate_generated` 组救回 **0/128**。
3. 成功候选族：**TURN_S 35 + SHIFT_TURN 27**；L/Z3/LEFT/Z5/DOWN_LOOP 救回数均为 0。
   即"扩大候选"的收益来自**冻结族的密集采样与重排序**，不是新几何族——新族 `DOWN_LOOP`
   能生成合法几何（见 5.2），但在当前稠密布局中全部被阻挡。
4. 分布：1600 档 pair 救回 ES 21 / EN 15 / SW 14 / NW 12；200→400 主在 ES（+11），
   400→800 主在 EN（+8）/NW（+8）。
5. 未救回 244 条（1600 档）三分类：**预算耗尽 3** / **当前布局阻挡 199** / **无候选生成 42**
   （42 条四档恒为 42）。几何拒绝原因聚合（1600 档）：double_cross 47,298（67.1%）、
   spacing 18,923（26.8%）、tangent_touch 4,306（6.1%）。
6. **阻挡高度集中**：Top-15 blocker 占总 blocker 命中 70,527 次的 40.0%，其中
   #750(ES) 6,891 次/影响 99 条失败路线、#885(SW) 4,128、#679(ES) 2,248、#760(ES) 2,171、
   #929(NW) 1,656。这一事实直接支撑"拥塞/顺序耦合是主要瓶颈"的判断（第 7 节 Q2）。

### 5.2 128 条角部路线的候选覆盖（任务 5.4 复核）

上一轮 128 条 `no_candidate_generated` 路线在旧生成器下 `evaluated=0`。本轮用扩展候选库
（全队列、与预算无关）复核：

| 口径 | 结果 |
|---|---|
| 空板布局下能生成合法几何候选 | **86/128**（共 2,903 条，均值 22.7，最大 90/条） |
| 空板候选来自哪些族 | **只来自 Z5（58 条路线 / 516 条）与 DOWN_LOOP（86 条路线 / 2,387 条）**；L/TURN_S/SHIFT_TURN/Z3/LEFT 贡献 0 |
| 冻结 206 布局下有任何可插入候选 | **0/128**（86 条是"能生成但全部被当前布局阻挡"） |
| 扩展候选库下仍生成不出任何候选 | **42/128**（ID: 618,625-628,633-636,638,641-644,649-652,657-658,769-774,777-780,785-786,1009-1012,1017-1022） |

强一致性校验：这 42 条 0 生成集合 = 四档 budget sweep 的 `no_candidate_generated` 集合 =
empty/base 覆盖集合（集合完全相等）；coverage 预测与 sweep 实测逐条不一致 0 条。

**独立随机探针（另一条实现路径，防止"生成器口径"自证）**：`v2opt/reachability_probe.py`
用 `candext.move_path` 的 move 语法（直线/quarter arc/短 S）做独立构造 + `canonical_validate`
验收，**不经过候选择优/截断**：

| 探针 | 规模 | 结果 |
|---|---|---|
| 确定性枚举（下降尾族 + 起终点短 S 变体） | 55,534 个构型 | 与扩展候选库一致的分类 |
| 随机探针（2~9 个转弯 move，直线长度解析求解到精确 q pose，固定 seed） | 128 条 × 20,000 次/线（实际采样 946,786 次） | **86/128 找到至少 1 条合法 D56 几何** |
| 延长预算（对前两阶段未找到的 42 条） | 42 条 × 100,000 次/线（合计 420 万次） | **新发现 = 0** |
| 预筛审计 | 已知合法候选 64/64 被接受；预筛拒绝 1,506/1,506 经 canonical_validate 复核同样拒绝 | 误拒 = 0（false negative 0） |
| 事后重验 | 86 条 probe-found 路线各取首条 moves 重算 | 86/86 合法 |

几何结构（README 详述）：128 条角部路线 sx∈[115.625,144.375]、qy∈[5.625,34.375]，
首步右转终点 x=sx+40∈[155.6,184.4] 全部越界，因此第一步只能左转；qy<40 又排除"常规右转
收尾"（需要弧前 y=qy-40<0）。收尾只能"下降左转"或"短 S"；42 条窄角路线
（sx∈[124.875,144.375]，qy∈[5.625,25.125]）的收尾弧与起点左转弧圆心距 < 80 mm、
交点落入两象限弧 → 必然自交；短 S 收尾又会把最后水平段压到 ≤150-sx（最小 5.625 mm）仍冲突。

**表述边界（重要）：** 以上只能说明"在**当前** D56 扩展候选库/枚举 + 固定端口切向 + R=40 +
150 mm 板 + 禁止自交的约束下，这 42 条没有找到合法候选"。这不是"二维物理上绝对不可布通"
的数学证明；更小的弯曲半径、自由角度或换一种 2D 曲线族可能连通它们（但那已超出本轮 D56 模型）。

### 5.3 E1：只扩大候选、不做强化 R&R

## 7. 科学问题回答

### Q1：V2 从 698 条出发，使用更多 D56 候选和强化 R&R，最多实际达到多少条？

**答案：752/1024（73.44%），比 698 组合基线 +54 条。**

分解：

| 组成 | 提升 | 来源 |
|---|---:|---|
| z1：V2-D 492 → Z1OPT 508 | +16 | 扩大候选顺序插入 +3（35/243/422）+ 强化 R&R +13（261/282/312/327/349/393/404/409/431/471/475/476/496） |
| z2：V2-C 206 → E3 244 | +38 | 扩大候选顺序插入 +37（E1 同结果）+ R&R 首轮早停 +1（route 528） |
| **合计** | **+54** | **698 + 54 = 752/1024** |

- z2 的 E1（只扩大候选）243、E2（原预算 + R&R）209、E3（扩大 + R&R）244、E3X（E3 + 更大
  R&R 搜索预算）244。E3X 的 0 增益说明 z2 的 244 不是"R&R 预算不足"，而是该布局下的实际可达值。
- z2 的独立插入实验（5.1 节）显示 62 条路线在冻结 206 布局下可独立插入；E3 只布入 38 条
  （37+1），剩余 24 条受顺序耦合限制。若实现顺序感知的插入优化，理论上还有 +10~24 条的空间，
  但这属于"组合调度优化"且无保证（见 Q4）。
- 剩余失败：z1 4 条（同 x 直连）、z2 268 条（42 条当前 D56 候选库无候选 + 226 条被占位/几何阻挡）。
- **所有新成功路线都经过冻结独立校验器 strict 审计，752 这个数字是独立验收后的数字。**

### Q2：布通率低的主要原因究竟是候选搜索不足、路线之间的拥塞冲突，还是 R40 对固定二维 D56 几何造成的可达性限制？

把 z2 的 306 条历史失败逐一归类（数字来自 5.1/5.2/5.3）：

| 失败类型 | 条数 | 占 306 | 证据 |
|---|---:|---:|---|
| **候选搜索不足（扩大搜索可独立救援）** | 62 | 20.3% | 冻结布局独立插入，预算 800 即可全部救回；其中 37 条已被 E1 实际布入 |
| **拥塞/顺序耦合（有合法候选但被已布路线挡住）** | 202 | 66.0% | 扩展候选库能生成候选，但冻结布局下不可插入；阻挡集中在少数路线（Top-15 占 40%）；E1 因顺序耦合少布 25 条 |
| **D56 几何可达性限制（当前候选库生成不出候选）** | 42 | 13.7% | 空板下扩展候选库 0 候选；均为固定端口切向 + R=40 的角部路线 |

- 若只看"候选预算"：历史 175 条 200 次评价耗尽确实是上一轮**表面**瓶颈，但本轮证明候选**生成器**
  在 800 评价内即饱和，单纯加预算的边际收益为 0。**候选搜索不足只解释了约 20% 的失败**。
- **主要原因是拥塞/顺序耦合（约 66%）**：同一批候选在独立测试与顺序提交之间损失 25/62；剩余
  202 条全部被已布路线阻挡，且少数关键路线占据了大比例阻挡命中。
- **其次是 D56 可达性限制（约 14%）**：128 条角部路线中 42 条在当前 D56 候选库下无任何合法候选，
  这是固定端口切向 + R=40 + 150 mm 板 + 禁止自交共同造成的几何墙，与预算/布局无关。
- 三类并非互斥：202 条拥塞失败中，若换一种 2D 曲线族（非 D56）可能找到绕行方案，因此"拥塞"的
  上界还受 D56 几何族限制；但就本轮可实验的 D56 而言，**拥塞是第一主因**。

### Q3：单路线候选搜索的收益是否逐渐饱和？强化 R&R 是否仍然有效？

**候选搜索：明确饱和。** 200→400→800 边际 = +20/+20，800→1600 = **+0**；成功候选在队列中的
位置最大 778，全部 <800。当前生成器的候选空间就是 800 左右，继续加预算没有意义。若要进一步
提高"候选搜索"的收益，必须扩大**候选生成空间**（更多轨道/更长 staircases/更多族），而不是预算；
但本轮的 42 条 0 候选角部路线表明，D56 内扩大生成空间对这些路线大概率也是无效的。

**R&R：有效但与布局结构强相关（不是普遍有效）。**
- z2：E2 +3（原预算）、E3 +1（扩大候选，首轮早停）；即使按 E3X 扩大 R&R 搜索预算，预期收益
  也只是个位数（见 5.5/E3X）。**在 z2 稠密布局上 R&R 接近饱和。**
- z1：R&R +13（失败 20 条中救回 13），**在可替代路线多的平面 R&R 依然有效**，
  轮次收益 +8 → +4 → 0 呈清晰饱和曲线。

### Q4：继续投入时间优化现有 D56 二维算法，还可能获得多大收益？判断必须基于实验数据，并说明不确定性。

基于本轮数据的分层估计（z2 平面）：

| 优化方向 | 可追加收益（乐观上界） | 依据与不确定性 |
|---|---|---|
| 顺序/调度优化（顺序感知插入，吸收 25 条顺序耦合损失） | +10~25 条 | E1 已布 37/62；独立测试 62 条全部合法，理论上换策略可接近 62。不确定：顺序耦合是 NP 难组合问题，实际能否再抓 10-25 条无保证 |
| R&R 搜索预算/多 seed/更大 group（E3X 类） | +2~8 条 | E2 +3、z1 R&R +13 显示结构条件；z2 稠密布局成功率低，E3X 实测见 5.5 |
| 候选生成空间再扩展（新 staircase/更长族） | +0~10 条 | 62 条可救援已全部来自冻结族；42 条 0 候选为几何墙；不确定性最大 |
| 角部路线专门几何（若允许不同 2D 曲线族） | 最多 +42 条（理论上限） | 但需超出 D56/固定端口切向模型 → 属"扩展二维几何模型"，不是 D56 调优 |
| **z2 现实上界** | **约 260~280/512** | 对应 1024 组合约 **768~788/1024（75%~77%）**；上述区间为工程估计，非实验证明 |

**结论：继续投入 D56 二维调优的期望收益约 +15~35 条（1024 中 +1.5%~3.4%），且呈递减；**
要突破 78% 必须改变几何族（更小 R 或自由角度，属工艺/模型变更）或引入 3D。

### Q5：对剩余失败路线，哪些问题有可能通过三维空间寻路缓解，哪些是固定端口切向和最小弯曲半径带来的限制、不能简单依靠增加维度解决？

| 失败类型 | 3D 能否缓解 | 理由 |
|---|---|---|
| 拥塞/顺序耦合（202 条，66%） | **能，且这是 3D 的主要价值** | 3D 让不同路线在不同高度穿越，直接消除"占位阻挡"；固定端口切向只在端口附近约束，可在离开端口后立即通过 z 向弯曲解耦 |
| 候选择优不足（62 条中未布入部分） | 能（同上，免去顺序耦合） | 3D 下不存在"先布占位"问题 |
| 固定端口切向 + R=40 的角部可达性（42 条无候选 + 部分 86 条） | **部分能，但需改变接口/工艺模型** | 若允许在端口附近就开始 z 向弯曲（z-transition/via/taper），则二维平面内的"必须先左转再绕回"约束消失；但当前真实 2×16 双高度模型明确"无 z 方向过渡"，两排端口固定在 z1/z2，因此**不能在本轮的接口模型里用 3D 解决**。若未来把端口附近 z 弯曲纳入工艺模型，则这 42 条大概率可解 |
| 最后 4 条 z1 同 x 直连 | 不能简单靠 3D 解决 | 其约束是"两端同一 x 坐标 + 固定切向"，2D 中唯一 D56 解是竖直线；3D 可绕行但需在端口处做 z 弯曲（同上，接口模型问题）。若 3D 仅在中间层绕行而端口仍要求平面内切向，则无解 |

**结论：3D 能缓解 66% 的拥塞型失败与部分候选型失败；但"固定端口切向 + R=40"的角部限制属于
接口/工艺模型约束，单纯"增加一个维度"不够，必须先明确 3D 接口的 z 向过渡方式。**

### 基于证据的最终建议

1. **不建议继续把主要精力投入现有 D56 二维算法的搜索/调度调优**：候选搜索在 800 评价处饱和，
   R&R 在稠密 z2 上接近饱和，D56 二维剩余空间约 +15~35 条（组合 ~768-788/1024），且
   大部分要来自"顺序/组合优化"这种高不确定性、低可解释性的工作。
2. **建议把本轮方法固化为 2D D56 基线交付**（E1/E3/Z1OPT 与 698/最优组合全部保留并独立验收），
   论文中把 698 → BEST 的提升与失败分类（20%/66%/14%）作为"二维 D56 已达到其结构上限"的证据。
3. **下一步主攻方向：Native 3D 联合寻路**，但需先做前置研究：
   (a) 明确 3D 接口的 z 向过渡方式（端口处是否允许 z 弯曲/via），这决定了 42 条角部路线能否解；
   (b) 3D 路由的曲率约束（R≥40 是否在 3D 曲线上仍然成立；若成立，需重新推导 3D 最小转弯空间）；
   (c) 在 3D 原型中先复现"拥塞型失败（202 条）能否被 3D 消除"作为可行性验证。
4. **不建议"扩展二维路径几何模型"作为主线**：在 R≥40 固定工艺下，更大半径只会更差；更小半径
   或自由角度属于工艺/模型变更，若工艺允许 R<40，则角部 42 条会迎刃而解，但这已不是 D56 算法问题，
   且需重新做工艺可行性论证。

## 11. 局限与不确定性

1. **候选族覆盖不完整**：本轮只扩展了 6 个冻结族 + 1 个新族（DOWN_LOOP）。"42 条角部路线无候选"
   只在**本轮候选库/枚举**意义下成立，不是物理不可布通的证明；`reachability/` 给出独立随机探针
   的证据与边界（见该目录 README）。
2. **R&R 的随机性**：R&R 是随机化过程（固定 seed，多 seed 可复现），E2/E3 的 +3/+1 是特定 seed 的
   结果；E3X 用更多事务/多 seed 探索同一布局，但它仍是启发式，不能证明"R&R 已达到理论最优"。
   受控 k 规模重放只完成了 A 组部分（见 5.5），B 组（blocker 最多 + 大 k 全量）未完成，
   相关结论以官方臂日志为准。
3. **E3 早停**：E3 官方臂因"首轮 0 增益即停"规则只跑了 1 轮（307 s），244 不能解读为 R&R 饱和；
   E3X 是对此的补充（4 轮 k 升级、128 事务/轮、0 增益），它是在 E3 结果上续跑，不是同一实验协议的
   重复；E3X 的"0 增益"与"k=8 无可构造交易"共同支持 z2 R&R 饱和的判断，但仍属实验证据而非证明。
4. **顺序耦合的代价**：E1 的 37 条 vs 独立测试 62 条，说明本实验的顺序策略仍有 25 条空间；
   但顺序优化是组合问题，本报告只用"独立测试"给出该代价的量化上界，没有实现顺序优化器。
5. **运行时间限制**：E3 的 R&R、E3X 的轮数用墙钟/事务上限控制；若给更多时间，收益可能略增，
   但 z2 的 R&R 结构条件（双方都要大范围重布）限制了量级。
6. **物理模型未验证**：R=40 mm、30 µm 间距、双高度 2×16 接口仍是实验约定，不是已确认工艺参数；
   交叉损耗/弯曲损耗未标定，本报告不声称可制造性。
7. **测量口径**：所有 routed 数均为 `validate_fslw` strict 审计后的数字；交叉数、传播损耗等指标
   由 frozen `fslw.metrics` 重新计算，不用于任何排序决策（排序只用 routed 数与几何合法性）。

## 12. 下一步研究建议（基于本轮实验）

1. **短期（论文收尾）**：固化 2D D56 基线（698 → BEST）与本轮方法（扩展候选 + 强化 R&R），
   把"失败三分类 20%/66%/14%"和"候选 800 饱和、R&R 结构依赖"写成 D56 二维的结构上限证据。
2. **中期（3D 前置研究）**：
   - 定义 3D 接口模型：端口处是否允许 z 弯曲/via；这决定 42 条角部路线与 4 条直连路线能否解；
   - 推导 3D 曲率约束（R≥40 是否作用于 3D 曲线；最小 3D 转弯空间）；
   - 用本轮 202 条拥塞型失败路线做 3D 可行性原型验证（目标：证明 3D 能消除拥塞型失败）。
3. **不建议继续的方向**：D56 二维候选预算继续加大（已饱和）、为 D56 增加更多同构候选族
   （收益 <10 条）、在 R≥40 下扩展二维几何（更大半径只会更差）。
