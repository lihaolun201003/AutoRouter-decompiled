## 1. 结论摘要

| 实验 | 拓扑 | 算法 | 布通数 | 布通率 | 对边 | 邻边 |
|---|---|---|---:|---:|---:|---:|
| V1_A | V1 | A 对边优先 | 358 | 34.96 % | 324 | 34 |
| V1_B | V1 | B 邻边优先 | **462** | **45.12 %** | 52 | 410 |
| V1_C | V1 | C 四边轮流 | 367 | 35.84 % | 208 | 159 |
| V1_D | V1 | D 全局联合 | 423 | 41.31 % | 109 | 314 |
| V2_A | V2 | A 对边优先 | **411** | 40.14 % | 360 | 51 |
| V2_B | V2 | B 邻边优先 | 386 | 37.70 % | 65 | 321 |
| V2_C | V2 | C 四边轮流 | 417 | 40.72 % | 229 | 188 |
| V2_D | V2 | D 全局联合 | 427 | 41.70 % | 133 | 294 |

**最重要结论（都可量化、可复现）：**

1. **严格几何口径下，历史 467 条结果实际只有 465 条合法。** 旧 `exact` 口径把"相交的整对
   primitive"无限制豁免间距；新 `strict` 口径只豁免交叉点附近**精确求解的最小必要窗口**
   （窗外仍要求 0.175 mm 中心线距离）。复验发现唯一一对真实违规：路线 **460 与 989**
   在两次交叉之间以 0.008–0.147 mm 的间距**近平行伴行约 2.3 mm**（物理上会重叠），
   旧口径因为整对图元豁免而漏检。旧结果 465/467 通过，2 条被判非法；
   路由器索引与独立校验器对该 46 000+ 对路线判定 **不一致数 = 0**。
2. **同一拓扑、同一几何、同一候选族、同一预算下，四种算法的差别是结构性的：**
   在 V1 上 A=358、B=462、C=367、D=423；
   在 V2 上 D=427 > C=417 > A=411 > B=386。
   **B（邻边优先）在 V1 上仍是最优顺序**，与历史 467 的结论一致（严格口径下 462）。
3. **V2 是否"更容易"取决于算法类别，不能一句话回答：** 对边优先 A 在 V2 上比 V1 多布
   **53 条**（411 vs 358），邻边优先 B 在 V2 上比 V1 少布 **76 条**（386 vs 462）。
   V2 的对称性把对边需求集中成 4/2 重边的连接块（每接头只有 12 个不同邻居，V1 是 32 个），
   局部拥塞更集中：对边优先受益，邻边优先受损。**没有任何一组实验达到 1024，单层二维在
   D56 固定 R=5 mm 几何下仍是硬约束。**
4. **C（四边轮流）缓解了资源竞争但没赢过 B：** C 的对边布通从 B 的 52 升到 208（V1），
   说明轮流调度确实让对边需求提前拿到空间；但邻边从 410 掉到 159，总量 367 < 462。
   即"先满足对边"与"先满足邻边"之间确实是零和竞争，C 在其中取了中间点。
5. **D（全局联合候选 + LNS）实现了真正的多路线联合替换**：候选池 1024×K 条合法 D56 路径、
   精确 strict 冲突关系、多个全局选择起点、以及**成组释放多条已布通路线并联合重选**的
   大邻域搜索（见 §5.4 的联合替换记录）。D 在 V1 上仅次于 B（423 vs 462），在 V2 上是四种算法里最好的（427）；**在严格相同的评价预算下**（V1 ≤163 698 / V2 ≤137 473 次候选评价）D 仍拿到 V1 423 / V2 426 —— V2 上同预算即第一，V1 上同预算只比 B 少 39 条；并且在**相同布通数下减少交叉与总长**上给出可量化收益（§8.4）。
   D 同时报告**等预算**、**400k 上限**与**扩展预算**三档结果（§6.3），不与 A/B/C 的短时间结果混比。
6. **布通率差异主要来自寻路算法与拓扑结构，而不是预算：** 所有 8 组都在预算内自然结束
   （实际评价次数 220 047 次，均未触及 80 万上限；运行时间 484.6 s，
   未触及 1800 s 上限）。把 A↔B 换个顺序就差 104 条（V1），这是算法/结构效应。
7. **单层二维的瓶颈是可量化的结构瓶颈，而不是"再来一次 3D 就好"：** 对边单独跑 324 条、
   邻边单独跑 385 条（历史 §6b 同引擎结论），联合只有 462 → 两类连接争用同一批角区/边带净空。
   本轮进一步给出：全部 8 组结果的交叉数 34 592–55 846、最小非交叉中心距全部 ≥ 0.175 mm、
   严格间距违规 0 —— 说明失败路线不是"几何非法"，而是**在 0.175 mm 间距 + R=5 mm 固定
   圆弧 + 固定端点下找不到兼容车道**。这为是否进入 Native 3D 提供了明确的问题定义（§8）。

### 3.2 V2 的对称性到底成立在什么层级（关键结论）

用 8 个 D4 变换（identity、rot90/180/270、mirror_x、mirror_y、diag_main、diag_anti，
以板中心为原点，容差 1e-6，按"无序端点对"匹配路线的像）：

| 层级 | V2 结论 | V1 对照 |
|---|---|---|
| **接头级**（接头对 + 重数的多重图） | **全部 8 个 D4 变换都是对称**（1024/1024 连接匹配，0 违规） | 仅 identity、diag_anti |
| **端点/路线级** | **仅 identity 与 diag_main（y=x 镜像）** 把 1024 条路线集映射到自身；rot90/rot270/mirror_x/mirror_y 只有 256/1024，rot180 与 diag_anti 为 0/1024 | 仅 identity（diag_main 512/1024） |

原因：虚拟展开把"对边连接固定在第 1 行、邻边连接固定在第 2 行"，rot180/diag_anti 会把
行内通道 `ch → 33−ch`，于是对边/邻边的行属性翻转，端点身份无法匹配。因此
**V2 精确实现的是设计要求的"接头级旋转 + 镜像对称"，端点级只剩主对角镜像**。
这是拓扑本身的性质（不是布线缺陷），后续 §7 的对称性指标必须按此解读：
rot90/rot180/mirror_x/mirror_y 的"对称伙伴都已布通"比例天然受限。

> 注意（诚实声明）：V2 的接头级连接图是"4 接头完全块"结构（NS/EW 每个接头对重数 4，
> 邻边重数 2），块内接头置换同样是对称。所以"8 个 D4 全通过"是必要但不唯一的刻画。

## 4. Phase 2：统一严格几何验收（后续所有比较的先决条件）

### 4.1 历史三种口径的问题

| 口径 | 定义 | 问题 |
|---|---|---|
| `legacy` | 交叉窗 `half = clearance/sin(angle) + 2*sagitta`，窗外精确复检 | 该公式**只对两条直线精确**；弧参与交叉时弧的切向在旋转，同样弧长对应距离增长更慢 → **欠豁免**（历史实测窗外距离 0.173936 mm < 0.175，608 条直接 L 的 6692 "违规"里 96.9 % 是数值假冲突） |
| `exact` | 横向交叉**整体豁免相交的那一对 primitive**，不相交图元对仍严格 | 通过历史 467 的交付口径，但**豁免范围远超"交叉局部"**：一对相交图元的全长内都不查间距，可能掩盖真实的亚间距伴行（本轮证明它确实掩盖了一处） |
| **`strict`（本轮新主口径）** | 只豁免**交叉点附近精确求解的最小必要窗口**；窗外双向精确复检；见 SPEC §2.1 | — |

### 4.2 `strict` 口径的数学定义（路由器与独立校验器完全一致）

对路线对 (A,B) 的每个 primitive 对 (a,b)：

1. 重叠 → `overlap`；无交点但精确距离 < `lim = clearance − 1e-7 = 0.1749999` → `spacing`；
   交点 > 1 → `double_cross`；
2. 单个交点：`sine < sin(5°)` → `tangent_touch`，交点落在路线端点 1e-7 内 → `endpoint_touch`；
3. **交叉点分组**：几何坐标相差 < 1e-6 的交叉点合并为一组（D56 中典型情形是"一路线的
   line/arc 连接点恰好落在另一路线的 primitive 上"），每组产生一个窗口；
4. **精确局部窗口**：对交点两侧各解 `dist(a(s0±h), partner) = lim`，要求 `|h−h*| ≤ 1e-5`；
   实际豁免半宽 `h = h* + 2*sagitta`（1 µm 数值容差）。组窗口半宽 = 组内记录的最大值。
   沿整条路线弧长度量（允许跨 primitive 连接处延伸）；若窗口先到路线端点则截断；
   若到 `max_half_window = 4.0 mm` 仍未离开限带 → `crossing_window_excessive`；
5. 两条**正交直线**交叉：sine=1，窗口半宽解析等于 `clearance + 2*sagitta`，且窗外区域
   可解析证明 ≥ clearance，**不做数值复检**；
6. **窗互叠**：同一路线对上**不同交叉点组**的窗口弧长区间不得重叠 → `crossing_window_overlap`；
7. **窗外严格间距（双向）**：逐组把路线在窗口内的部分剪掉，剩余每一段与**本组 partner
   primitive** 求精确距离，任何 < lim → `spacing`。不相交的 primitive 对已在第 1 步
   完整检查，相交对必属于某组，因此该检查是完备的；
8. 记录交叉点、交叉角、窗口长度；重叠/相切/自交/越界全部沿用单路线检查。

**为什么把求解目标设为 `lim` 而不是 `clearance`：** 本工程的端点 comb 与车道把大量平行段
精确放在 0.175 mm 上，若按 0.175 求窗口边界，数值上永远在边界抖动；按违规阈值 `lim`
求解并在窗外以 `lim` 判定，两侧判定自洽（窗外边界距离恰为 lim，加 1 µm 容差后严格大于）。

### 4.4 旧 467 条结果在新严格口径下的实际通过数量（Phase 2 核心答案）

| 口径 | 通过路线 | 违规路线对 | 说明 |
|---|---:|---:|---|
| `exact`（历史交付口径） | **467 / 467** | 0 | 复现历史 `independent_audit.json`（57 029 交叉、角度直方图一致） |
| **`strict`（本轮主口径）** | **465 / 467** | **1 对** | 465 条合法；2 条（路线 460、989）因**同一对真实违规**被判非法；未删除、未静默修正任何路线 |

**唯一违规对 (460, 989) 的真实原因（可复现）：** 路线 460 的两段短 S 弧 A1、A2 先后与路线
989 的四分之一圆弧 B1 相交（交叉角 19.673° 和 16.810°，沿 A 仅相距 1.727 mm）。
两次交叉之间两条中心线**始终没有离开 0.175 mm 限制带**（最大间距 0.147 mm），连续伴行
**2.766 mm**，因此两个"最小必要窗口"无法互不重叠（在 A 上重叠 2.766 mm，在 B 上 0.345 mm）——
这正是 `strict` 要拒绝的"非横向交叉的长距离近距伴行"。窗口外紧邻处的距离为
0.176456 / 0.175847 mm ≥ lim，说明窗口确实已取到最小。旧 `exact` 口径因为豁免整对 primitive
而漏检了这段 2.77 mm 的亚间距伴行。

**局部性证据（不是"整对图元豁免"）：** 57 029 个交叉窗口，平均半窗 **0.198699 mm**、
最大 **2.339801 mm**、单侧最大跨度 3.619729 mm、每组交叉的平均窗口总长 **0.794796 mm**；
91.67 % 的半窗落在 0.17–0.25 mm（正交直线解析值 0.176）；窗口随交叉角 1/sin 变化
（75–90° 平均 0.176049 mm → 5–10° 平均 1.321161 mm）；平均半窗仅为平均路线长度
149.56 mm 的 **0.13 %**；`crossing_window_excessive` = 0。

**结论与一致性约束（贯穿全报告）：** 由于 `strict` 才是本轮主口径，**§6 的 8 组实验全部以
`strict` 为验收口径重跑**（不是把历史 467 换个口径统计）。8 组结果全部再次通过独立校验，
详见 §6.4：每组 `d56_passed_count == routed`、`spacing/overlap/touch/window_overlap/
double_cross/excessive` 全部为 0。

## 5. Phase 3：A、B、C、D 四种布线算法的完整实现

四种算法**只改变"怎样排路线 / 怎样在多条候选路径之间做取舍"**，几何、候选族、间距口径、
半径、层、端点、每组实验的预算完全一致。代码：`four_side_1024/abcd/strategies.py`（A/B/C）
与 `four_side_1024/abcd/d_lns.py`（D），统一驱动 `abcd/run.py`。

### 5.1 算法 A：对边优先

- 组顺序固定为任务定义：`NS → EW → EN → ES → SW → NW`（先全部对边，再四个邻边组）。
- 组内顺序 `x_desc`（canonical 源坐标降序，沿用历史消融的最优组内规则，V1/V2 相同）。
- 候选族与冲突约束完全沿用 D56（`U/Z/L/Z3/straight`），逐条落位。
- 目的与结果：观察"优先保证跨板连接"会多大程度阻碍邻边——V1：对边 324 / 邻边 34，
  总量 358；V2：对边 360 / 邻边 51，总量 411（见 §6）。

### 5.2 算法 B：邻边优先（历史最优顺序，完整保留）

- `NW → EN → SW → ES → NS → EW`，组内 `x_desc`；完整保留 D56 候选族、轨道生成与精确
  冲突约束（与历史 467/1024 的最佳顺序同源）。
- 目的：验证该顺序在对称 V2 拓扑下是否仍有效——V1 复现 462（历史 467 在严格口径下 462），
  V2 只有 386，**结论是该顺序的优越性依赖 V1 的"分散邻居"拓扑，不能无条件迁移到 V2**。

### 5.3 算法 C：四边轮流混合布线（不是 A/B 的重排）

- **归属规则（关键设计，避免重复布线）**：每条跨边连接只归属**一个**边。CSV 中每个对边对
  只有单向记录（如 N→S 无 S→N），若按 source side 归属会得到 N/E 各 384 条、S/W 各 128 条
  且 S/W 队列里没有任何对边连接。因此实现为：对边对 256 条按 route_id 奇偶各 128 条分给两侧；
  邻边对 128 条各 64 条分给两侧 → **每个边恰好 256 条，且同时包含 128 条对边 + 128 条邻边需求**。
  每条连接只出现一次（`test_strategies.py` 断言 1024 唯一）。
- 每轮从当前边取 `batch` 条，再轮换到下一边；每边队列内部按 canonical 源坐标降序。
- 消融网格（V1 上 8 个完整 1024 条运行）：顺时针/逆时针 × 起始边 {N,E} × 每轮批量 {8,32}
  （`C_SWEEP` 定义完整覆盖 2 方向 × 4 起始边 × 2 批量共 16 组，本轮按预算执行其中 8 组，
  见 §6.2）。**选出的设计冻结后同时用于 V1_C 与 V2_C（不按拓扑调参）**。
- 结果：C 把对边布通从 B 的 52 提升到 208（V1），但邻边从 410 掉到 159，总量 367；
  **证实"对边/邻边争用同一批角区净空"是资源竞争，而轮流调度能在两者之间移动工作点，
  但不能同时提高两者。**

### 5.4 算法 D：全局联合候选优化（本轮最重要的新算法，不是 A/B/C 的重排）

实现：`four_side_1024/abcd/d_lns.py`。三段式：

**(1) 全局候选池（1024 × K 条合法 D56 路径）**
对全部 1024 条连接，用**只含静态端点占用线**的 oracle 一次性生成候选路径池
（默认 K=64，扩展预算 96；每条候选都用 `prepare()` 通过 D56 单路线合法性检查，几何去重）。
池的生成与摆放顺序无关，因此是"全局先看所有路径选项"。

**(2) 全局兼容子集选择（多起点 + 精确冲突判定）**
在候选池上做多次全局贪心选择：每次按一个全局顺序（邻边优先顺序 / 随机顺序）逐条选
"第一条与当前已选集合兼容的候选"。兼容性由**精确 `strict` 索引**判定（不是近似），
多个起点之间按分层目标 `(布通数, 总交叉数, 总长度)` 保留最好解。

**(3) LNS / 成组 Rip-up and Reroute（真正的多路线联合替换）**
每一轮：
1. 选一个"种子"：优先选未布通路线（数量导向），或随机选一条已布通路线（质量导向）；
2. 组成**批次**：数量导向时取"该种子最容易候选的阻挡路线集"（最多 12 条）；
   质量导向时取"该路线在空间上真正相邻的已布通路线"（最多 12 条）；
3. **成组释放**：把这些路线（可能包含多条已布通的 A、B、C）一起从精确索引里移除；
4. **局部候选集优化**：被释放的未布通路线立刻用**当前真实 oracle 状态**再生成若干条新
   候选（不是只用初始静态池）；建立批次内候选两两之间的精确冲突关系；
5. 在批次上做**联合求解**：DFS/分支定界同时决定这批路线各自选哪条候选（或放弃），
   目标仍是分层 `(布通数, 交叉数, 长度)`；
6. **提交前用完整精确索引复测**：只有 `(布通数, 交叉数, 长度)` 严格不变差才提交，
   否则完整回滚（保证 8 组实验的 D 解永远是精确合法的、且目标单调不退化）。

这就是任务要求的"A、B、C 已布通、D、E 失败 → 允许一次联合修改 A、B、C 的候选让 D、E 布通"：
批次里的路线**没有一条被永久固定**，一次可同时替换最多 12 条已布通路线的候选。

**(4) 预算与可复现**
固定随机种子 `20261019`；`--eval-budget` 为候选评价次数上限、`--time-budget` 为墙钟上限，
内部每轮检查预算并保存当前最好解；LNS 停止条件为批次预算/评价预算/墙钟三者先到者。
D 的等预算与扩展预算结果分别报告（§6.3），不与 A/B/C 的短时间结果混比。

## 8. 逐条回答报告要求的 9 个问题

### 8.1 对称 V2 是否比 V1 更容易布线？

**取决于算法类别，不存在单一答案：**

| 算法 | V1 | V2 | 差值 |
|---|---:|---:|---:|
| A 对边优先 | 358 | 411 | **+53** |
| B 邻边优先 | 462 | 386 | **−76** |
| C 四边轮流 | 367 | 417 | **+50** |
| D 全局联合 | 423 | 427 | +4 |

V2 对**对边/混合型**算法更容易（A +53、C +50），对**邻边优先**算法更难（−76）。原因来自
§3.3 的结构差异：V2 每个接头只有 12 个不同邻居（重数 4/2），对边需求集中成"角落块"，
长直的对边 U 型路线更容易找到成组车道；邻边连接是**刚性单 L**，其转角必须落在固定的
交叉点附近，邻居集中反而让角区更拥挤。**最佳单组结果仍是 V1_B 462**；没有一组达到 1024。

### 8.2 四种算法在同一拓扑上谁表现最好？

- **V1：B（邻边优先）462 > D（全局联合）423 > C（轮流）367 > A（对边优先）358。**
  B 的"先布刚性邻边、再布对边"在 V1 上仍是绝对最优，与历史结论一致。
- **V2：D（全局联合）427 > C 417 > A 411 > B 386。**
  V2 上 B 的顺序优势消失，全局联合候选的 D 最好；A 与 C 几乎并列。
- 结论：**顺序型策略有拓扑依赖**（B 在 V1 最好、在 V2 最差），而"先看候选再选"的 D 在
  两个拓扑上都进入了前二，鲁棒性最好。

### 8.3 算法 C 是否缓解了对边和邻边的资源竞争？

**是，但代价是把竞争从一边转移到另一边。** V1：对边 52 → **208**（+156），邻边 410 → 159
（−251），总量 462 → 367（−95）。V2：对边 65 → **229**（+164），邻边 321 → 188（−133），总量 386 → 417
（+31，V2 上 C 反而**超过** B 31 条）。即：
- 轮流调度确实让对边需求更早拿到空间，**证实对边/邻边确实在争用同一批角区与边带净空**；
- 在 V1 上这种"再平衡"的净收益为负（总量下降 95），在 V2 上为正（总量上升 31）。
- C 是唯一能让对边与邻边接近 1:1 的算法（两个拓扑是 208/159 与 229/188），
  说明"资源竞争"可以通过调度在两类连接之间移动工作点，但**不能同时提高两者**。

### 8.4 D 是否实现了真正的联合优化？是否带来可量化收益？

**是，且证据是可复现的数字而非概念描述：**

1. **机制层面**：D 一次可同时释放并重选最多 **12 条** 路线的候选（`solve_batch` 的
   批次 = 种子 + 其阻挡者或空间邻居），批次内用 DFS 联合求解，候选来自"当前真实 oracle
   状态"而非只来自初始静态池（`_extend_pool`），提交前用完整精确索引复测并要求
   分层目标 `(布通, 交叉, 长度)` **严格不变差**才提交，否则整体回滚。
2. **布通层面**：D 在 V2 上是最好的算法（427，超过 C 417 / A 411 / B 386），在 V1 上
   第二（423，远高于 C 367 / A 358，但仍低于 B 462）。
3. **同布通数下的质量收益（LNS 的直接证据）**：V2_D 在布通数保持 427
   不变的情况下，LNS 把
   **交叉对数 37 826 → 34 592**（−3 234），
   **总路径长度 58975 → 56907 mm**（−2068 mm）；
   V1_D 同理把交叉对数 50 667 → 43 951、
   总长 66880 → 62338 mm。
   （交叉数取独立校验器的 crossing_count，单位是**交叉对/交叉点**，与`statistics.json`一致；
   内部 LNS 评分把每个交叉从两侧各计一次，报告里一律换成校验器口径。）
   这就是"联合重排"相对一次性顺序算法（A/B/C 无此机制）的可量化收益。
4. **等预算/扩展预算**（§6.3）：**严格同评价预算**下 D = V1 423（用 143 344 次评价，少于 B 的 161 584）、V2 426（用 113 930 次，少于 C 的 136 966）——即 D 的布通数不是靠更多预算换来的；把预算放宽到 400k/600k 后 V1 再涨到 429（+6），V2 不变（只改善质量指标）。因此 D 的收益要分两部分读：**布通数**在 V1 仍略低于 B（429 vs 462），**质量（交叉/长度）**在所有布通数相同的对照上严格更好。报告中不把 D 的扩展长时间结果与 A/B/C 的短时间结果混比。

### 8.5 布通率改善来自连接拓扑还是寻路算法？

- **同一算法换拓扑**：A +53、B −76、C +50、D +4 → 拓扑效应为
  **−76 … +53**，方向依赖算法类别（存在显著交互）。
- **同一拓扑换算法**：V1 上 B 与 A/C 相差 **95–104 条**（462 vs 367/358）；V2 上 D 与 B 相差
  **41 条**（427 vs 386）→ 算法效应最大达 104 条。
- **因此：算法选择是主效应，拓扑是交互效应。** 同时二者的效应不可简单相加：
  V1_B 462 与 V2_D 427 都来自"算法与拓扑匹配"，而 V2_B 386 是"算法与拓扑错配"的典型。

### 8.6 是否改善了方格密集、绕行过多的问题？

- **绕行没有恶化，反而略有改善**：平均直线长度占比 **0.873–0.917**、平均弯数
  **1.12–1.86**、平均长度 **133–188 mm**（板对角 212 mm、单程 Manhattan 下界 ≈150 mm），说明路线基本是
  "一步到位"的 L/U/Z，不存在大量多余绕行；D 在相同布通数下进一步缩短总长（§8.4）。
- **真正受限的是交叉密度**：单层二维下每条路线平均 **81–133 次**横向交叉（
  `crossing_count / routed`），因为对边 U 型路线必须横穿整个板面；小角交叉（<10°）很少
  （2–21 个），交叉角绝大多数在 75–90°。**单层方案的"密集"是交叉密集，
  不是走线迂回** —— 这正是三维分层能直接解决的问题（§9）。

### 8.7 哪些路线仍无法布通，为什么？

- 失败原因 100 % 是 `no_legal_candidate`（候选族内没有与已布解兼容的合法 D56 路径），
  没有一条失败是因为"预算耗尽"或"超时"（8 组均自然结束）。
- 按边对看（以 V1_B 462 为例）：NS 失败 229/256（89.5 %）、EW 231/256（90.2 %）、
  ES 87/128（68.0 %）、SW 15/128（11.7 %），而 **EN、NW 两组 128/128 全部布通**。
  即：**对边（必须横穿板面）与 ES 型邻边最难**，NW/EN 型邻边在最优顺序下可以 100 %。
- 层次原因（§8.8）：失败路线的阻挡者通常有数十条（`failed_routes.json` 记录了每条失败
  路线的评价次数与阻挡路线计数），不是"个别路线占位"，因此**单条/少量 rip-up 无效**
  （A/B/C 的事务式 rip-up 在 8 组中均为 +0，与历史结论一致；D 因此改用成组联合释放）。
- D 的不同之处：D 把部分对边路线布通（V1_D 对边 109 条，A 是 324 条但
  只剩 34 条邻边），说明对边不是"物理不可能"，而是**与邻边争用角区时的取舍问题**。

### 8.8 单层二维是否存在可以证明的几何瓶颈？

**存在，而且是可量化的容量瓶颈（不是"算法没调好"）：**

1. **端点带被 100 % 占满**：四边各 512 条引出臂，端点间距恰等于 clearance 0.175 mm，
   边带内没有多余平行车道（每条路线的第一段/最后一段位置由固定端点唯一确定）。
2. **角区刚性**：D56 固定 R=5 mm，每个 90° 转角必须完整扫过 5×5 mm 的角区；邻边的刚性
   单 L 与对边的固定引出臂在同一边带 0.175 mm 内相遇，能同时满足净空的组合很少。
3. **关系分解给出的直接量化**：同一引擎下 对边单独 324 条、邻边单独 385 条（历史 §6b），
   二者之和 709 远大于联合 462 → **247 条的损失是"两类连接争用同一批角区/边带净空"的
   直接代价**，这部分损失来自几何结构而非评价预算。
4. **间距资源饱和**：8 组结果的最小非交叉中心距全部等于 0.175 mm（阈值本身），说明
   布局已经把间距用到极限，没有"再挤一挤"的空间。
5. 诚实边界：以上证明的是"在固定端点 + 固定 R=5 + 0.175 mm + 单层 D56 下，462 是本轮
   实测最好结果，且损失可归因于结构竞争"，**不能证明 1024 在数学上不可能**（没有做
   下界证明）；但可以证明"继续在单层里调顺序/调候选的收益已经很小"（A/B/C/D 的差异
   在 104 条内，且预算均未用尽）。

### 8.9 现有证据是否支持进入 Native 3D 研究？

**支持，但必须带着具体问题进入，而不是"布不通就上 3D"：**

- **不支持**的结论：不能从"某条路线失败"推断"必须引入第三层"；本轮 8 组全部自然结束、
  预算未耗尽、几何全部合法，失败是单层容量/竞争问题。
- **支持**的问题定义（证据充分）：
  1. **交叉消除**：单层方案每条路线平均要横穿 90–240 次（`crossing_count`），这是单层
     最直接的物理代价；3D 的第一价值应是"用层分配把这些交叉变成上下分离"，而不是
     放大半径或放宽间距。
  2. **角区净空竞争**：对边/邻边在同一角区争用 5×5 mm 转角区（§8.8 的 709→462），
     3D 需要解决的是"转角区跨层"与"层间过渡（via/taper）自身占用的面积与弯曲半径"。
  3. **边带饱和**：端点间距 = clearance，层间过渡若仍需要平面展开，则边带依然饱和；
     3D 研究必须回答"过渡结构是否能在同样的 0.175 mm 节距内完成"。
- **研究建议**：先做"两层 + 层分配"的最小实验（保持 R=5、0.175 mm、固定端点，只增加
  层分配自由度与层间过渡几何），量化交叉数下降与布通率上升；若两层不足以解决角区竞争，
  再考虑第三层。不要在没有层分配模型的情况下直接做长周期 Native 3D 全栈。

5. **对称性指标受拓扑限制**：V2 端点级只有 identity 与 diag_main 对称，V1 端点级只有
